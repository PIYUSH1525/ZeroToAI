      7. Python Implementation: Multi-Head Attention From Scratch in PyTorch
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Here is a complete, runnable PyTorch implementation of <strong className="text-white">Multi-Head Attention</strong> showing how professional LLM code splits <code>d_model</code> into <code>num_heads</code> using <code>.view()</code> and <code>.transpose()</code>—running all heads in parallel without a single Python loop:
      </div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3">
          <span className="font-mono text-xs font-semibold text-teal-400">multi_head_attention.py</span>
          <span className="font-mono text-[11px] text-slate-400">Python 3.11+ · PyTorch 2.x</span>
        </div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block text-cyan-300">import math</span>
            <span className="block text-cyan-300">import torch</span>
            <span className="block text-cyan-300">import torch.nn as nn</span>
            <span className="block">import torch.nn.functional as F</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">class MultiHeadAttention(nn.Module):</span>
            <span className="block">    def __init__(self, dModel: int, numHeads: int):</span>
            <span className="block">        super().__init__()</span>
            <span className="block">        assert dModel % numHeads == 0, &quot;dModel must be divisible by numHeads!&quot;</span>
            <span className="block">        self.dModel = dModel</span>
            <span className="block">        self.numHeads = numHeads</span>
            <span className="block text-violet-300">        self.dHead = dModel // numHeads                  # e.g., 512 // 8 = 64 sliders per head</span>
            <span className="block">&nbsp;</span>
            <span className="block">        self.wQ = nn.Linear(dModel, dModel, bias=False)</span>
            <span className="block">        self.wK = nn.Linear(dModel, dModel, bias=False)</span>
            <span className="block">        self.wV = nn.Linear(dModel, dModel, bias=False)</span>
            <span className="block text-emerald-300">        self.wO = nn.Linear(dModel, dModel, bias=False)  # Final Mixing Desk (W_O)</span>
            <span className="block">&nbsp;</span>
            <span className="block">    def forward(self, x: torch.Tensor) -&gt; torch.Tensor:</span>
            <span className="block">        B, T, C = x.shape</span>
            <span className="block">&nbsp;</span>
            <span className="block">        # 1. Project Q, K, V and split C into (numHeads, dHead) -&gt; Transpose to (B, H, T, dHead)</span>
            <span className="block text-violet-300">        Q = self.wQ(x).view(B, T, self.numHeads, self.dHead).transpose(1, 2)</span>
            <span className="block text-violet-300">        K = self.wK(x).view(B, T, self.numHeads, self.dHead).transpose(1, 2)</span>
            <span className="block text-violet-300">        V = self.wV(x).view(B, T, self.numHeads, self.dHead).transpose(1, 2)</span>
            <span className="block">&nbsp;</span>
            <span className="block">        # 2. Run Scaled Dot-Product Attention across all H heads in parallel!</span>
            <span className="block">        scores = (Q @ K.transpose(-2, -1)) / math.sqrt(self.dHead)      # Shape: (B, H, T, T)</span>
            <span className="block">        weights = F.softmax(scores, dim=-1)</span>
            <span className="block">        headOutputs = weights @ V                                       # Shape: (B, H, T, dHead)</span>
            <span className="block">&nbsp;</span>
            <span className="block">        # 3. Concatenate all H heads back into (B, T, dModel) and mix with W_O!</span>
            <span className="block text-cyan-300">        glued = headOutputs.transpose(1, 2).contiguous().view(B, T, C)</span>
            <span className="block text-emerald-300">        return self.wO(glued)                                           # Shape: (B, T, dModel)</span>
            <span className="block">&nbsp;</span>
            <span className="block">torch.manual_seed(42)</span>
            <span className="block">mha = MultiHeadAttention(dModel=512, numHeads=8)</span>
            <span className="block">sampleInput = torch.randn(2, 10, 512)                                   # 2 sentences, 10 words, 512 sliders</span>
            <span className="block">output = mha(sampleInput)</span>
            <span className="block text-emerald-300">print(&quot;Input Shape:&quot;, sampleInput.shape, &quot;-&gt; MHA Output Shape:&quot;, output.shape)</span>
          </code>
        </pre>
      </div>
      <div className="rounded-xl border border-teal-500/20 bg-teal-500/[0.05] p-5 text-sm leading-7 text-slate-300">
        <div className="mb-2 font-bold text-teal-300">
          Pro Tip (Why Do We Need .contiguous() Before .view(B, T, C)?):
        </div>
        <div>
          Look at Step 3 in the code above: <code>headOutputs.transpose(1, 2).contiguous().view(B, T, C)</code>. In PyTorch, calling <code>.transpose(1, 2)</code> swaps the axes without rearranging the numbers in RAM. Calling <strong className="text-white"><code>.contiguous()</code></strong> neatly lines the numbers up in memory row-by-row so <code>.view(B, T, C)</code> can glue the $8$ heads of $64$ back into $512$ without throwing a PyTorch stride error!
        </div>
      </div>
    </div>

      Common Mistakes
    </h2>
    <div className="rounded-2xl border border-rose-500/25 bg-rose-950/[0.15] p-6 sm:p-8">
      <div className="space-y-6">
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Choosing a d_model that is not evenly divisible by num_heads.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Because every head gets $d_{\text{model}} / H$ sliders, picking $d_{\text{model}} = 512$ with $H = 12$ crashes immediately ($512 / 12 = 42.66$). Always pick $H$ that divides $d_{\text{model}}$ cleanly (like $512 / 8 = 64$ or $768 / 12 = 64$).
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Scaling attention scores by sqrt(d_model) instead of sqrt(d_head).
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Each individual head computes a dot product over $d_{\text{head}} = 64$ numbers, not $d_{\text{model}} = 512$. Always divide scores by $\sqrt{d_{\text{head}}}$ (e.g., $\sqrt{64} = 8$)!
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Calling .view(B, T, C) directly after .transpose(1, 2) without .contiguous() (or .reshape()).
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Transposing the head and sequence dimensions makes the tensor non-contiguous in memory. Always call <code>.contiguous().view(B, T, C)</code> or <code>.reshape(B, T, C)</code> when concatenating heads back together.
          </div>
        </div>
