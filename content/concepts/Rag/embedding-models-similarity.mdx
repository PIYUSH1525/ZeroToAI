  <section>
    <h2 className="mb-6 border-l-4 border-violet-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">2. Intermediate: Cosine, Dot Product and Euclidean Distance</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Three measures are used to compare two vectors $a$ and $b$ with $d$ dimensions.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">$$a \cdot b = \sum_{i=1}^{d} a_i b_i \qquad \cos\theta = \dfrac{a \cdot b}{\lVert a \rVert \, \lVert b \rVert} \qquad \lVert a - b \rVert = \sqrt{\sum_{i=1}^{d} (a_i - b_i)^2}$$</div>
      <div className="grid gap-5 md:grid-cols-3">
        <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-violet-300">Dot product</div>
          <div className="text-sm leading-7">Grows with both direction match and vector length. A long vector can score high even if its direction is only roughly right.</div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Cosine similarity</div>
          <div className="text-sm leading-7">Looks only at direction. Vector length is ignored, so it compares meaning rather than size.</div>
        </div>
        <div className="rounded-xl border border-orange-500/25 bg-orange-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-orange-300">Euclidean distance</div>
          <div className="text-sm leading-7">The straight-line distance between the two points. Smaller means more similar, the opposite direction to the other two.</div>
        </div>
      </div>
      <div className="rounded-xl border border-violet-500/20 bg-violet-500/[0.05] p-5"><strong className="text-violet-300">Beware:</strong> dot product and cosine are similarities where bigger is better, while Euclidean is a distance where smaller is better. Mixing up the direction of a metric silently returns the worst results first.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Intermediate: Normalization and Which Metric to Use</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>A vector is <strong className="text-white">normalized</strong> when its length is scaled to exactly 1. For normalized vectors the three measures agree on the ranking, because dot product equals cosine and the squared Euclidean distance becomes $2 - 2\cos\theta$. Many modern embedding models already return normalized vectors, which makes the metric choice less risky.</div>
      <div className="space-y-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Rule 1.</strong> Use the metric the model was trained with. The model documentation says which.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Rule 2.</strong> Make the vector database use the same metric. A mismatch is a common silent bug.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Rule 3.</strong> If you normalize at indexing time, normalize query vectors the same way.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Rule 4.</strong> When unsure, cosine similarity on normalized vectors is a safe default.</div>
      </div>
    </div>
  </section>

    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Embedding choices have production consequences. Some models are trained so that you can keep only the first part of each vector, or you can store numbers with fewer bits (quantization). Both cut memory and search time at the price of a small drop in quality that you should measure.</div>
      <div>The most important consequence is <strong className="text-white">switching cost</strong>. Vectors from two models cannot be mixed, so changing the model means re-embedding every chunk. Plan for this from day one:</div>

        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Record</strong> the model name, version and settings as metadata for every index.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Build</strong> the new index next to the old one instead of editing it in place.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Compare</strong> retrieval quality on your test questions with both indexes.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Switch</strong> traffic to the new index and keep the old one briefly in case you need to roll back.</div>

  <section>
    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">7. Python Implementation: Comparing the Three Metrics</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The program defines the three measures from scratch and compares one query against three documents with very different vector lengths. First the raw vectors are ranked by each metric, then the vectors are normalized to length 1 and the ranking is repeated. The last column checks the identity that squared distance equals 2 minus 2 cosine for unit vectors.</div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3"><span className="font-mono text-xs font-semibold text-teal-400">similarity_metrics.py</span><span className="font-mono text-[11px] text-slate-400">Python 3.10+ · Standard library only</span></div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">import math</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def dot(a, b):</span>
            <span className="block">    return sum(x * y for x, y in zip(a, b))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def norm(a):</span>
            <span className="block">    return math.sqrt(dot(a, a))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def cosine(a, b):</span>
            <span className="block">    return dot(a, b) / (norm(a) * norm(b))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def euclid(a, b):</span>
            <span className="block">    return math.sqrt(sum((x - y) * (x - y) for x, y in zip(a, b)))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def normalize(a):</span>
            <span className="block">    n = norm(a)</span>
            <span className="block">    return [x / n for x in a]</span>
            <span className="block">&nbsp;</span>
            <span className="block">query = [1.0, 1.0]</span>
            <span className="block">docs = [</span>
            <span className="block">    (&quot;A same direction, long&quot;, [4.0, 4.0]),</span>
            <span className="block">    (&quot;B short, nearly same direction&quot;, [1.0, 0.8]),</span>
            <span className="block">    (&quot;C other direction, very long&quot;, [9.0, 1.0]),</span>
            <span className="block">]</span>
            <span className="block">&nbsp;</span>
            <span className="block">print(&quot;Raw vectors&quot;)</span>
