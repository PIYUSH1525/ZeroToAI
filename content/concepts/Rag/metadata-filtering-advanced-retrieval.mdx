  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Intermediate: Pre-Filtering vs Post-Filtering</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The order of filtering and searching matters a great deal.</div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-rose-500/25 bg-rose-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-rose-300">Post-filtering</div>
          <div className="text-sm leading-7">Search first, take the top k, then remove results that fail the filter. Easy to build, but the top k may be full of disallowed chunks, leaving few or no results.</div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Pre-filtering</div>
          <div className="text-sm leading-7">Restrict the search to allowed chunks, then rank them and take the top k. You get k valid results, but the index must support it efficiently.</div>
        </div>
      </div>
      <div>Many vector databases support <strong className="text-white">filtered search</strong> natively, applying the conditions while they walk the index. This gives the benefit of pre-filtering without scanning everything. Whenever you evaluate a database, test what happens when a filter is very strict, because performance and recall can both change.</div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5"><strong className="text-emerald-300">Rule of thumb:</strong> use pre-filtering, or native filtered search, for any rule that must hold. Use post-filtering only for soft preferences where getting fewer results is acceptable.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: Multiple Filters and Retrieval Constraints</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Real questions combine rules. Treat each rule as either a <strong className="text-white">hard constraint</strong> that must hold, or a <strong className="text-white">soft preference</strong> that only adjusts the score.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-slate-200">
            <tr><th className="px-4 py-3">Kind</th><th className="px-4 py-3">Behavior</th><th className="px-4 py-3">Example</th></tr>
          </thead>
          <tbody className="divide-y divide-white/10">
            <tr><td className="px-4 py-3 font-semibold text-white">Hard constraint</td><td className="px-4 py-3">Chunks that fail are removed</td><td className="px-4 py-3">Status active, user has access</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Soft preference</td><td className="px-4 py-3">Chunks that match get a score boost</td><td className="px-4 py-3">More recent documents rank slightly higher</td></tr>
          </tbody>
        </table>
      </div>
      <div>Filters can also come from the question itself. A request such as last year HR policy contains a department and a date. A language model or simple rules can extract these into filter fields, a technique often called self-querying. It is powerful but risky: a wrong guess silently hides the correct answer. Log extracted filters, and fall back to an unfiltered search when the filtered one returns nothing.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">5. Advanced: Access Control Done Safely</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Permission filters protect confidential data, so they need stricter handling than other filters.</div>
      <div className="space-y-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Enforce on the server.</strong> Apply the permission filter in your retrieval code, using the verified identity of the caller. Never rely on asking the model to ignore chunks it should not mention.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Filter before the prompt.</strong> A forbidden chunk that reaches the prompt can leak, because the model may quote it.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Isolate tenants.</strong> Use a mandatory tenant field on every record, and make the filter impossible to skip.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Test adversarially.</strong> Write tests where a user asks directly for content they must not see, and check that nothing comes back.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Keep metadata correct.</strong> A wrong or missing label is a silent leak or a silent miss, so validate metadata at ingestion.</div>
      </div>
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5"><strong className="text-cyan-300">Remember:</strong> when the filtered result is empty, say so honestly. Do not widen the filter on your own to find something, because that may violate the rule the filter was enforcing.</div>
    </div>
  </section>

    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">7. Python Implementation: Pre-Filter vs Post-Filter</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The program holds seven chunks, each with a department and a year. A simple word-overlap score ranks them. It then runs the same query three ways: with no filter, with the rule applied after taking the top 3 results, and with the rule applied before ranking.</div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3"><span className="font-mono text-xs font-semibold text-teal-400">metadata_filtering.py</span><span className="font-mono text-[11px] text-slate-400">Python 3.10+ · Standard library only</span></div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">chunks = [</span>
            <span className="block">    (&quot;c1&quot;, &quot;hr&quot;, 2023, &quot;vacation policy: 15 days per year&quot;),</span>
            <span className="block">    (&quot;c2&quot;, &quot;hr&quot;, 2024, &quot;vacation policy: 18 days per year&quot;),</span>
            <span className="block">    (&quot;c3&quot;, &quot;hr&quot;, 2025, &quot;vacation policy: 20 days per year&quot;),</span>
            <span className="block">    (&quot;c4&quot;, &quot;finance&quot;, 2025, &quot;travel policy: book flights two weeks ahead&quot;),</span>
            <span className="block">    (&quot;c5&quot;, &quot;finance&quot;, 2023, &quot;vacation travel refunds are not covered&quot;),</span>
            <span className="block">    (&quot;c6&quot;, &quot;it&quot;, 2025, &quot;laptop policy: replace every 3 years&quot;),</span>
            <span className="block">    (&quot;c7&quot;, &quot;hr&quot;, 2025, &quot;holiday calendar for the year&quot;),</span>
            <span className="block">]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def words(text):</span>
            <span className="block">    return set(&quot;&quot;.join(ch if ch.isalnum() else &quot; &quot; for ch in text.lower()).split())</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def score(query, text):</span>
            <span className="block">    return len(words(query) &amp; words(text))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def search(query, k, allowed=None, filter_first=True):</span>
            <span className="block">    pool = chunks if not filter_first or allowed is None else [c for c in chunks if allowed(c)]</span>
            <span className="block">    ranked = sorted(pool, key=lambda c: (-score(query, c[3]), c[0]))[:k]</span>
            <span className="block">    if not filter_first and allowed is not None:</span>
            <span className="block">        ranked = [c for c in ranked if allowed(c)]</span>
            <span className="block">    return [c[0] for c in ranked]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def rule(chunk):</span>
            <span className="block">    return chunk[1] == &quot;hr&quot; and chunk[2] &gt;= 2025</span>
            <span className="block">&nbsp;</span>
            <span className="block">query = &quot;vacation policy&quot;</span>
            <span className="block">print(&quot;Filter: department hr and year 2025 or later&quot;)</span>
            <span className="block">print(&quot;Search with no filter    :&quot;, search(query, 3))</span>
            <span className="block">print(&quot;Post-filter (top 3 first):&quot;, search(query, 3, rule, filter_first=False))</span>
            <span className="block">print(&quot;Pre-filter (filter first):&quot;, search(query, 3, rule, filter_first=True))</span>
          </code>
        </pre>
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5">
        <div className="mb-2 text-xs font-bold uppercase tracking-wider text-emerald-400">Expected output</div>
        <pre className="overflow-x-auto font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">Filter: department hr and year 2025 or later</span>
            <span className="block">Search with no filter    : [&apos;c1&apos;, &apos;c2&apos;, &apos;c3&apos;]</span>
            <span className="block">Post-filter (top 3 first): [&apos;c3&apos;]</span>
            <span className="block">Pre-filter (filter first): [&apos;c3&apos;, &apos;c7&apos;]</span>
          </code>
        </pre>
      </div>
      <div>Without a filter, the top three results are the vacation policies from 2023, 2024 and 2025, so the user gets two outdated answers. Post-filtering removes the old ones but leaves only a single result, because the top three slots were already used up. Pre-filtering searches only chunks that pass the rule, so it returns every valid chunk up to the limit. Note that the second pre-filter result scores 0 for this query, so in practice you would pair filtering with a minimum score.</div>
