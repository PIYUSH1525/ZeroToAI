<section>
  <h2 className="mb-6 border-l-4 border-blue-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">1. Beginner: One System, Two Pipelines</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>Think of a restaurant. Before opening, the kitchen does the <em>prep</em>: washing, chopping and storing ingredients so they are ready. When a customer orders, the kitchen does the <em>service</em>: it grabs the right prepared ingredients, cooks the dish and serves it fast. Nobody chops onions while the customer waits.</div>
    <div className="grid gap-5 md:grid-cols-2">
      <div className="rounded-xl border border-blue-500/25 bg-blue-500/[0.04] p-5">
        <div className="mb-2 font-semibold text-blue-300">Indexing pipeline = prep kitchen</div>
        <div className="text-sm leading-7">Collects documents, cleans them, cuts them into chunks, converts each chunk into numbers, and stores everything in a searchable index. It is <strong className="text-white">offline</strong>: it runs before users ask anything, or in the background when documents change.</div>
      </div>
      <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
        <div className="mb-2 font-semibold text-violet-300">Query pipeline = service</div>
        <div className="text-sm leading-7">Takes one user question, finds the best chunks in the index, builds a prompt and generates the answer. It is <strong className="text-white">online</strong>: a real person is waiting, so it must be fast.</div>
      </div>
    </div>
    <div className="rounded-xl border border-blue-500/20 bg-blue-500/[0.05] p-5">
      <strong className="text-blue-300">The meeting point:</strong> the <strong className="text-white">index</strong>. The indexing pipeline writes to it and the query pipeline reads from it. Keeping the heavy work on the writing side is what makes answering quick.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-violet-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">2. Beginner: The Indexing Pipeline (Offline)</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>Indexing has five stages. Each one turns the data into a form that is a little more ready for search.</div>
    <div className="space-y-3">
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-blue-300">Stage 1 · Load.</strong> Read documents from their sources: PDFs, web pages, wikis, databases. The output is raw text plus information about where it came from.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-blue-300">Stage 2 · Clean.</strong> Remove junk such as page headers, menus and duplicate copies, and normalize the text so it is consistent.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-blue-300">Stage 3 · Chunk.</strong> Split long documents into smaller pieces called <strong className="text-white">chunks</strong>. A model cannot search or read a whole book at once, and small focused pieces match questions better. A 3,000-word document cut into pieces of about 200 words gives roughly 15 chunks.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-blue-300">Stage 4 · Embed.</strong> Convert each chunk into an <strong className="text-white">embedding</strong>: a list of numbers that captures its meaning, so that chunks about similar things end up with similar numbers.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-blue-300">Stage 5 · Store.</strong> Save each embedding together with its original chunk text and <strong className="text-white">metadata</strong> (the source file, a document id, a date) in a vector store, so results can later be shown with their sources.</div>
    </div>
    <div className="rounded-xl border border-violet-500/20 bg-violet-500/[0.05] p-5">
      <strong className="text-violet-300">Why do it offline?</strong> Embedding thousands of chunks takes time and money. Doing it once, and again only for new or changed documents, means no user ever waits for it.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Beginner: The Query Pipeline (Online)</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>When a user types a question, the system runs six steps, usually in well under a few seconds:</div>
    <div className="grid gap-4 md:grid-cols-3">
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">1 · Receive</div>
        <div className="mt-2 text-sm leading-7">Accept the question and any extra information, such as which user is asking.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">2 · Embed the query</div>
        <div className="mt-2 text-sm leading-7">Turn the question into an embedding, using the same embedding model as the documents.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">3 · Retrieve</div>
        <div className="mt-2 text-sm leading-7">Search the index and return the top-k chunks whose embeddings are closest to the question.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">4 · Build the prompt</div>
        <div className="mt-2 text-sm leading-7">Combine instructions, the retrieved chunks and the question into one prompt.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">5 · Generate</div>
        <div className="mt-2 text-sm leading-7">Send the prompt to the LLM, which writes an answer using the supplied context.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">6 · Return</div>
        <div className="mt-2 text-sm leading-7">Show the answer to the user, ideally with the sources it came from.</div>
      </div>
    </div>
    <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5">
      <strong className="text-emerald-300">One rule you must never break:</strong> the question and the documents must be embedded by the <strong className="text-white">same embedding model</strong>. Embeddings from two different models live in different number spaces, so comparing them is meaningless.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: Offline vs Online Processing</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>Because the two pipelines run at different times, they have different goals. Good engineers design them separately.</div>
    <div className="overflow-x-auto rounded-xl border border-white/10">
      <table className="w-full text-left text-sm">
        <thead className="bg-white/[0.04] text-slate-200">
          <tr>
            <th className="px-4 py-3">Aspect</th>
            <th className="px-4 py-3">Indexing (offline)</th>
            <th className="px-4 py-3">Query (online)</th>
          </tr>
        </thead>
        <tbody className="divide-y divide-white/10">
          <tr><td className="px-4 py-3 font-semibold text-white">When it runs</td><td className="px-4 py-3">Before launch, then on a schedule or when documents change</td><td className="px-4 py-3">Every time a user asks</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Main goal</td><td className="px-4 py-3 text-blue-300">Quality and completeness of the index</td><td className="px-4 py-3 text-violet-300">Low latency and good answers</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Speed pressure</td><td className="px-4 py-3">Low: can take minutes or hours</td><td className="px-4 py-3">High: users wait</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Typical cost</td><td className="px-4 py-3">Embedding every chunk</td><td className="px-4 py-3">One query embedding, one search, one LLM call</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">If it fails</td><td className="px-4 py-3">Index is missing or stale</td><td className="px-4 py-3">User sees an error or a bad answer right now</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Touches the index</td><td className="px-4 py-3">Writes</td><td className="px-4 py-3">Reads</td></tr>
        </tbody>
      </table>
    </div>
    <div className="rounded-xl border border-orange-500/20 bg-orange-500/[0.05] p-5">
      <strong className="text-orange-300">Design consequence:</strong> any step that can be moved from online to offline usually should be. Pre-computing embeddings, cleaning text and attaching metadata all happen in indexing so the query path stays short.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">5. Advanced: The Context Budget and Where the Pipeline Grows</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>The heart of the query pipeline is the hand-off <strong className="text-white">retrieval → context → generation</strong>. Retrieval returns a ranked list of chunks with scores. <strong className="text-white">Context construction</strong> decides which chunks to keep, in what order, and how to format them. Generation then reads that context together with the instructions and the question.</div>
    <div>Everything the model reads, plus the answer it writes, must fit inside the context window. This gives a simple budget rule:</div>
    <div className="overflow-x-auto rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">$$T_{prompt} + T_{answer} \le T_{window}$$</div>
    <div>Here $T$ counts tokens. For example, take 4 chunks of about 300 tokens each, a 100-token instruction and a 30-token question. The prompt is $4 \times 300 + 100 + 30 = 1{,}330$ tokens. If you reserve 500 tokens for the answer, the total is 1,830 tokens, comfortably inside typical windows. The budget matters because retrieving more chunks is not free: extra text costs money, adds delay, and can bury the one passage that matters.</div>
    <div>The basic pipeline above is the foundation. Real systems add stages around it, and each one has its own lesson later in this course:</div>
    <div className="overflow-x-auto rounded-xl border border-white/10">
      <table className="w-full text-left text-sm">
        <thead className="bg-white/[0.04] text-slate-200">
          <tr>
            <th className="px-4 py-3">Added stage</th>
            <th className="px-4 py-3">Where it goes</th>
            <th className="px-4 py-3">What it improves</th>
          </tr>
        </thead>
        <tbody className="divide-y divide-white/10">
          <tr><td className="px-4 py-3 font-semibold text-white">Query rewriting</td><td className="px-4 py-3">Before retrieval</td><td className="px-4 py-3">Vague or messy questions</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Metadata filtering</td><td className="px-4 py-3">During retrieval</td><td className="px-4 py-3">Relevance, permissions, freshness</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Hybrid search and reranking</td><td className="px-4 py-3">Retrieval and after it</td><td className="px-4 py-3">Ranking quality</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Citations</td><td className="px-4 py-3">Generation and output</td><td className="px-4 py-3">Trust and checking</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Evaluation and monitoring</td><td className="px-4 py-3">Around the whole system</td><td className="px-4 py-3">Finding and fixing failures</td></tr>
        </tbody>
      </table>
    </div>
  </div>
</section>

          <span className="block">]</span>
          <span className="block">&nbsp;</span>
          <span className="block">stop_words = set([&quot;the&quot;, &quot;is&quot;, &quot;a&quot;, &quot;of&quot;, &quot;how&quot;, &quot;many&quot;, &quot;much&quot;, &quot;does&quot;, &quot;do&quot;, &quot;per&quot;, &quot;to&quot;, &quot;can&quot;, &quot;for&quot;, &quot;on&quot;, &quot;get&quot;, &quot;gets&quot;])</span>
          <span className="block">&nbsp;</span>
          <span className="block text-slate-500"># Shared tools: used by BOTH pipelines (same vectorizer for docs and queries)</span>
          <span className="block text-cyan-300">def vectorize(text):</span>
          <span className="block">    cleaned = &quot;&quot;.join(ch for ch in text.lower() if ch.isalnum() or ch == &quot; &quot;)</span>
          <span className="block">    return Counter(w for w in cleaned.split() if w not in stop_words)</span>
          <span className="block">&nbsp;</span>
          <span className="block text-cyan-300">def cosine(a, b):</span>
          <span className="block">    dot = sum(a[w] * b[w] for w in set(a) &amp; set(b))</span>
          <span className="block">    norm_a = math.sqrt(sum(v * v for v in a.values()))</span>
          <span className="block">    norm_b = math.sqrt(sum(v * v for v in b.values()))</span>
          <span className="block">    if norm_a == 0 or norm_b == 0:</span>
          <span className="block">        return 0.0</span>
          <span className="block">    return dot / (norm_a * norm_b)</span>

          <span className="block text-slate-500"># ===== OFFLINE PIPELINE: chunk, embed, store =====</span>

          <span className="block">    return [s.strip() + &quot;.&quot; for s in text.split(&quot;.&quot;) if s.strip()]</span>

          <span className="block">    return index</span>

          <span className="block text-slate-500"># ===== ONLINE PIPELINE: retrieve, build prompt, generate =====</span>
          <span className="block text-emerald-300">def retrieve(question, index, k=2):</span>
          <span className="block">    q = vectorize(question)</span>
          <span className="block">    scored = [(cosine(q, vec), source, piece) for source, piece, vec in index]</span>
          <span className="block">    scored.sort(reverse=True)</span>
          <span className="block">    return scored[:k]</span>
          <span className="block">&nbsp;</span>
          <span className="block text-emerald-300">def build_prompt(question, hits):</span>
          <span className="block">    lines = [&quot;Answer using ONLY the context.&quot;, &quot;Context:&quot;]</span>
          <span className="block">    for score, source, piece in hits:</span>
          <span className="block">        lines.append(&quot;- &quot; + piece + &quot; (&quot; + source + &quot;)&quot;)</span>
          <span className="block">    lines.append(&quot;Question: &quot; + question)</span>
          <span className="block">    return lines</span>
          <span className="block">&nbsp;</span>
          <span className="block text-slate-500"># Stand-in for the LLM call: it just reads the first context line</span>
          <span className="block text-emerald-300">def generate(prompt):</span>
          <span className="block">    first = prompt[2]</span>
          <span className="block">    text, source = first[2:].rsplit(&quot; (&quot;, 1)</span>

          <span className="block">&nbsp;</span>

          <span className="block">]</span>
          <span className="block">&nbsp;</span>
          <span className="block">for question in questions:</span>
          <span className="block">    hits = retrieve(question, index, k=2)</span>
          <span className="block">    print(&quot;Question:&quot;, question)</span>
          <span className="block">    for score, source, piece in hits:</span>
          <span className="block">        print(&quot;  hit&quot;, round(score, 3), source, &quot;|&quot;, piece)</span>
          <span className="block">    prompt = build_prompt(question, hits)</span>
          <span className="block">    print(&quot;  Prompt:&quot;)</span>
          <span className="block">    for line in prompt:</span>
          <span className="block">        print(&quot;    &quot; + line)</span>
          <span className="block">    print(&quot;  Answer:&quot;, generate(prompt))</span>
          <span className="block">    print(&quot;&quot;)</span>
        </code>
