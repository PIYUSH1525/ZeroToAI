<section>
  <h2 className="mb-6 border-l-4 border-blue-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">1. Beginner: Where RAG Knowledge Comes From</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>Imagine moving into a new office where every colleague hands you notes in a different format: printed reports, sticky notes, spreadsheets, a filing cabinet. Before you can use any of it, you have to read it all and copy the useful parts into one notebook. That notebook is your knowledge base, and the copying work is document processing.</div>
    <div>Data sources fall into three broad families:</div>
    <div className="grid gap-5 md:grid-cols-3">
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-blue-400">Unstructured</div>
        <div className="mt-2 text-sm leading-7">Free-flowing text with no fixed fields: PDFs, Word documents, emails, meeting notes, transcripts.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-violet-400">Semi-structured</div>
        <div className="mt-2 text-sm leading-7">Text wrapped in markup that adds structure: HTML pages, Markdown files, JSON documents, XML.</div>
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="text-sm font-bold uppercase tracking-wider text-emerald-400">Structured</div>
        <div className="mt-2 text-sm leading-7">Data in rows and columns with named fields: CSV files, spreadsheets, SQL databases.</div>
      </div>
    </div>
    <div className="rounded-xl border border-blue-500/20 bg-blue-500/[0.05] p-5">
      <strong className="text-blue-300">Key point:</strong> the model never sees a PDF or a database. It only ever sees text in a prompt. Everything in this lesson is about converting each format into trustworthy text.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-violet-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">2. Beginner: Document Parsing and Text Extraction</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div><strong className="text-white">Parsing</strong> means reading a file according to the rules of its format. <strong className="text-white">Text extraction</strong> means pulling the human-readable content out of that parsed file. Together they turn a file into a record with three parts:</div>
    <div className="grid gap-5 md:grid-cols-3">
      <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
        <div className="mb-2 font-semibold text-violet-300">Text</div>
        <div className="text-sm leading-7">The clean content itself, with menus, scripts and layout noise removed.</div>
      </div>
      <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
        <div className="mb-2 font-semibold text-violet-300">Structure</div>
        <div className="text-sm leading-7">Useful shape worth keeping, such as headings, page numbers, list items and table cells.</div>
      </div>
      <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
        <div className="mb-2 font-semibold text-violet-300">Metadata</div>
        <div className="text-sm leading-7">Facts about the text: source path or URL, file type, title, author, date, access level.</div>
      </div>
    </div>
    <div>The steps are always the same: <em>fetch</em> the raw file, <em>parse</em> it with a tool that understands the format, <em>extract</em> text and structure, and <em>attach</em> metadata. Only the parser changes from format to format.</div>
    <div className="rounded-xl border border-violet-500/20 bg-violet-500/[0.05] p-5">
      <strong className="text-violet-300">Garbage in, garbage out:</strong> if a PDF parser merges two columns into one jumbled line, the chunk is unreadable, its embedding is meaningless, and no retrieval trick can recover it later. Always read some extracted text yourself.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Intermediate: PDFs, Office Files and Web Pages</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div><strong className="text-white">PDFs</strong> are the most common and the trickiest source. A PDF is designed to look the same on every screen, so it stores characters at exact positions on a page rather than as flowing paragraphs. A parser has to rebuild the reading order, and that can go wrong in four typical ways:</div>
    <div className="grid gap-4 md:grid-cols-2">
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Multiple columns.</strong> Lines from neighboring columns get interleaved.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Headers and footers.</strong> Page numbers and running titles repeat inside every page of text.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Tables.</strong> Cells flatten into a stream of numbers with no labels.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Scanned pages.</strong> A scan is just a picture of text, so a normal parser finds nothing. It needs <strong className="text-white">OCR</strong> (optical character recognition), which reads text out of images.</div>
    </div>
    <div>Libraries such as pypdf, PyMuPDF and pdfplumber extract text from digital PDFs; OCR tools such as Tesseract handle scans. <strong className="text-white">Word documents</strong> (.docx) are easier because they store real paragraphs and headings; a library such as python-docx reads them directly.</div>
    <div><strong className="text-white">Web pages</strong> bring a different problem: the useful article is surrounded by navigation menus, cookie banners, ads, footers and scripts. If you index all of it, those repeated fragments appear in thousands of chunks and pollute search results. Good extraction keeps the main content and the page title, and drops the boilerplate. Also remember that some pages build their content with JavaScript after loading, so a simple download may return an almost empty page.</div>
    <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5">
      <strong className="text-emerald-300">Markdown and plain text</strong> are the friendliest sources: they are already close to clean text, and their headings mark natural boundaries that later chunking steps can use.
    </div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: Structured Sources: CSV, JSON and Databases</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>Rows and columns are easy for a computer to read but awkward for a language search. A row such as <em>Pro plan, 25, available</em> has no meaning without its column names. The standard fix is to <strong className="text-white">verbalize</strong> each row: turn it into a short sentence that carries the labels, for example <em>The Pro plan costs 25 dollars and is available.</em> That sentence can be embedded and retrieved like any other text.</div>
    <div className="overflow-x-auto rounded-xl border border-white/10">
      <table className="w-full text-left text-sm">
        <thead className="bg-white/[0.04] text-slate-200">
          <tr>
            <th className="px-4 py-3">Source</th>
            <th className="px-4 py-3">How to turn it into text</th>
            <th className="px-4 py-3">Watch out for</th>
          </tr>
        </thead>
        <tbody className="divide-y divide-white/10">
          <tr><td className="px-4 py-3 font-semibold text-white">CSV</td><td className="px-4 py-3">One sentence per row, using the header names</td><td className="px-4 py-3 text-rose-300">Huge numeric tables embed poorly</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">JSON</td><td className="px-4 py-3">Choose the text fields; keep key names for meaning</td><td className="px-4 py-3 text-rose-300">Deep nesting and irrelevant fields</td></tr>
          <tr><td className="px-4 py-3 font-semibold text-white">Database</td><td className="px-4 py-3">Run a query or view, then verbalize the result rows</td><td className="px-4 py-3 text-rose-300">Permissions and data that changes quickly</td></tr>
        </tbody>
      </table>
    </div>
    <div>Databases deserve one extra thought. Do not dump a whole table into the index. Select only the columns that carry meaning, and decide whether the data should be copied into the index (fast, but can go stale) or queried live (fresh, but slower). For numeric questions such as <em>what was total revenue in March?</em>, retrieving text is the wrong tool; a later lesson on SQL and structured-data RAG covers that case.</div>
  </div>
</section>

<section>
  <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">5. Advanced: Extraction Quality and Metadata You Cannot Skip</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>Strong teams measure extraction instead of trusting it. Here are four cheap checks:</div>
    <div className="space-y-3">
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Read samples.</strong> Open ten random extracted documents and read them next to the originals.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Check lengths.</strong> A 40-page report that yields 200 characters has clearly failed. Very short or very long outputs deserve a look.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Look for garbled characters.</strong> Strange symbols usually mean a wrong text encoding or a broken font mapping.</div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-cyan-300">Measure coverage.</strong> For PDFs, count how many pages produced text.</div>
    </div>
    <div>Coverage gives a quick scan detector:</div>
    <div className="overflow-x-auto rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">$$\text{coverage} = \dfrac{\text{pages with extracted text}}{\text{total pages}}$$</div>
    <div>If only 12 of 40 pages produce text, the coverage is $12 / 40 = 0.30$. That strongly suggests that most pages are scanned images, so those pages need OCR instead of normal extraction.</div>
    <div><strong className="text-white">Metadata</strong> is the second thing teams regret skipping. Record it at extraction time, because it is almost impossible to reconstruct later:</div>
    <div className="grid gap-5 md:grid-cols-2">
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5">
        <div className="mb-2 font-semibold text-cyan-300">What to record</div>
        <div className="text-sm leading-7">Source path or URL, file type, title, page or section, author or owner, last modified date, and an access label saying who may see it.</div>
      </div>
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5">
        <div className="mb-2 font-semibold text-cyan-300">What it enables later</div>
        <div className="text-sm leading-7">Citations, filtering by date or department, duplicate detection, freshness checks and permission-aware retrieval.</div>
      </div>
    </div>
    <div className="rounded-xl border border-amber-500/25 bg-amber-500/[0.05] p-5">
      <strong className="text-amber-300">A responsibility note:</strong> only index content you are allowed to use, and carry its access rules along as metadata. Once a confidential file is mixed into a shared index without labels, it is very hard to separate again.
    </div>
  </div>
</section>

<section>
  <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">7. Python Implementation: Five Sources, One Record Format</h2>
  <div className="space-y-6 text-[16px] leading-8 text-slate-300">
    <div>The program below builds five tiny sources in memory: an HTML page, Markdown lines, CSV lines, a JSON string and an in-memory SQLite database. One small function per format turns each into clean text, and all results are collected into the same <code>(source, type, text)</code> record shape. It uses only the Python standard library. PDFs are left out because they need a third-party library; the same record shape would apply to them.</div>
    <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
      <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3">
        <span className="font-mono text-xs font-semibold text-teal-400">document_processing.py</span>
        <span className="font-mono text-[11px] text-slate-400">Python 3.10+ · Standard library only</span>
      </div>
      <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
        <code>
          <span className="block text-cyan-300">import csv</span>
          <span className="block text-cyan-300">import json</span>
          <span className="block text-cyan-300">import sqlite3</span>
          <span className="block text-cyan-300">from html.parser import HTMLParser</span>
          <span className="block">&nbsp;</span>
          <span className="block text-slate-500"># 1. HTML: keep visible text, skip style and script content</span>
          <span className="block text-violet-300">class TextExtractor(HTMLParser):</span>
          <span className="block">    def reset(self):</span>
          <span className="block">        super().reset()</span>
          <span className="block">        self.parts = []</span>
          <span className="block">        self.skip = 0</span>
          <span className="block">&nbsp;</span>
          <span className="block">    def handle_starttag(self, tag, attrs):</span>
          <span className="block">        if tag in (&quot;script&quot;, &quot;style&quot;):</span>
          <span className="block">            self.skip += 1</span>
          <span className="block">&nbsp;</span>
          <span className="block">    def handle_endtag(self, tag):</span>
          <span className="block">        if tag in (&quot;script&quot;, &quot;style&quot;):</span>
          <span className="block">            self.skip -= 1</span>
          <span className="block">&nbsp;</span>
          <span className="block">    def handle_data(self, data):</span>
          <span className="block">        if self.skip == 0 and data.strip():</span>
          <span className="block">            self.parts.append(data.strip())</span>
          <span className="block">&nbsp;</span>
          <span className="block text-cyan-300">def from_html(html):</span>
          <span className="block">    parser = TextExtractor()</span>
          <span className="block">    parser.feed(html)</span>
          <span className="block">    return &quot; &quot;.join(parser.parts)</span>
          <span className="block">&nbsp;</span>
          <span className="block text-slate-500"># 2. Markdown: remove heading and bullet symbols at the start of lines</span>
          <span className="block text-cyan-300">def from_markdown(lines):</span>
          <span className="block">    cleaned = [line.lstrip(&quot;#- &quot;).strip() for line in lines]</span>
          <span className="block">    return &quot; &quot;.join(cleaned)</span>
          <span className="block">&nbsp;</span>
          <span className="block text-slate-500"># 3. CSV: turn every row into a sentence that keeps the column meaning</span>
          <span className="block text-cyan-300">def from_csv(lines):</span>
          <span className="block">    sentences = []</span>
