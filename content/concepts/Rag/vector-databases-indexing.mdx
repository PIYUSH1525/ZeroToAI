A <strong className="text-white">vector database</strong> stores vectors together with their text and metadata, and builds an <strong className="text-white">index</strong> that makes nearest-neighbor search fast.   <section>
    <h2 className="mb-6 border-l-4 border-blue-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">1. Beginner: What a Vector Store Keeps and Does</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>A vector store is built around one record type. Every record holds four things, and all four are needed by RAG.</div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-blue-500/25 bg-blue-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-blue-300">Id</div>
          <div className="text-sm leading-7">A unique key, such as a chunk id, used to update or delete the record.</div>
        </div>
        <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-violet-300">Vector</div>
          <div className="text-sm leading-7">The embedding, which is what similarity search runs on.</div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Text</div>
          <div className="text-sm leading-7">The original chunk, which is what the model finally reads.</div>
        </div>
        <div className="rounded-xl border border-orange-500/25 bg-orange-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-orange-300">Metadata</div>
          <div className="text-sm leading-7">Source, date, version, permissions and other fields for filtering and citations.</div>
        </div>
      </div>
      <div>The basic operations are simple: <strong className="text-white">upsert</strong> (insert or update a record), <strong className="text-white">query</strong> (return the nearest records to a vector, optionally with a metadata filter), and <strong className="text-white">delete</strong>.</div>
    </div>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Intermediate: Exact Search and the Scale Problem</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The simplest search is <strong className="text-white">brute force</strong>, also called a flat index: compare the query with every stored vector and keep the best. It is exact, easy to build and perfectly fine for small collections. The cost grows linearly. With $N$ vectors of dimension $d$, one query needs about $N \times d$ multiplications.</div>
      <div>For 10 million vectors of 768 dimensions that is $10{,}000{,}000 \times 768 = 7{,}680{,}000{,}000$ operations for a single query. With many users asking at once, that is too slow and too expensive, so large systems search only part of the data.</div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5"><strong className="text-emerald-300">Do not over-engineer:</strong> for a few hundred thousand chunks or fewer, exact search is often fast enough, and it never misses the true best match. Reach for approximate indexes when measurements show you need them.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: Approximate Nearest Neighbor Search</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div><strong className="text-white">Approximate nearest neighbor (ANN)</strong> indexes organize vectors so a query can skip most of them. They occasionally miss a true neighbor, so quality is measured by <strong className="text-white">recall</strong>, the share of the exact top results that the index finds:</div>
      <div className="overflow-x-auto rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">$$\text{recall@}k = \dfrac{\lvert \text{ANN top-}k \cap \text{exact top-}k \rvert}{k}$$</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-slate-200">
            <tr><th className="px-4 py-3">Index family</th><th className="px-4 py-3">Main idea</th><th className="px-4 py-3">Typical trade-off</th></tr>
          </thead>
          <tbody className="divide-y divide-white/10">
            <tr><td className="px-4 py-3 font-semibold text-white">Cluster based (IVF)</td><td className="px-4 py-3">Group vectors into clusters, search only the closest few clusters</td><td className="px-4 py-3">Fast and compact; recall depends on how many clusters you probe</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Graph based (HNSW)</td><td className="px-4 py-3">Link each vector to near neighbors and walk the graph toward the query</td><td className="px-4 py-3">Very good recall and speed; uses more memory</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Compression (quantization)</td><td className="px-4 py-3">Store shortened or lower precision vectors</td><td className="px-4 py-3">Saves memory; slight loss of accuracy</td></tr>
          </tbody>
        </table>
      </div>
      <div>These ideas are often combined, for example clusters plus compression. The tuning knobs always trade recall against speed and memory.</div>
    </div>
  </section>

      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5"><strong className="text-cyan-300">Remember filtering and updates:</strong> metadata filters interact with the index, since filtering after a search can leave too few results, and some index types are slow to update or delete. Check how your chosen database handles both before you commit.</div>
    </div>

    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">7. Python Implementation: Exact Search vs a Cluster Index</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The program generates 2,000 vectors in 20 natural groups, then builds a simple cluster index: it picks 20 centroids, runs three rounds of re-centering, and stores which vectors belong to each cluster. A query is answered by probing only the closest few clusters. For 50 test queries it compares the approximate top 5 with the exact top 5 and reports recall and the number of distance checks.</div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3"><span className="font-mono text-xs font-semibold text-teal-400">ivf_search_demo.py</span><span className="font-mono text-[11px] text-slate-400">Python 3.10+ · Standard library only</span></div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">import random</span>
            <span className="block">&nbsp;</span>
            <span className="block">random.seed(7)</span>
            <span className="block">DIM = 8</span>
            <span className="block">N = 2000</span>
            <span className="block">K = 20</span>
            <span className="block">&nbsp;</span>
            <span className="block">centers = [[random.random() for j in range(DIM)] for i in range(K)]</span>
            <span className="block">vectors = []</span>
            <span className="block">for i in range(N):</span>
            <span className="block">    c = centers[i % K]</span>
            <span className="block">    vectors.append([x + (random.random() - 0.5) * 0.3 for x in c])</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def dist2(a, b):</span>
            <span className="block">    return sum((x - y) * (x - y) for x, y in zip(a, b))</span>
            <span className="block">&nbsp;</span>
            <span className="block">centroids = [vectors[i * (N // K)] for i in range(K)]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def assign():</span>
            <span className="block">    lists = [[] for c in range(K)]</span>
            <span className="block">    for idx, v in enumerate(vectors):</span>
            <span className="block">        nearest = min(range(K), key=lambda c: dist2(v, centroids[c]))</span>
            <span className="block">        lists[nearest].append(idx)</span>
            <span className="block">    return lists</span>
            <span className="block">&nbsp;</span>
            <span className="block">for step in range(3):</span>
            <span className="block">    lists = assign()</span>
            <span className="block">    for c in range(K):</span>
            <span className="block">        if lists[c]:</span>
            <span className="block">            centroids[c] = [sum(vectors[i][j] for i in lists[c]) / len(lists[c]) for j in range(DIM)]</span>
            <span className="block">lists = assign()</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def exact_search(q, k):</span>
            <span className="block">    return sorted(range(N), key=lambda i: dist2(q, vectors[i]))[:k]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def ivf_search(q, k, nprobe):</span>
            <span className="block">    order = sorted(range(K), key=lambda c: dist2(q, centroids[c]))[:nprobe]</span>
            <span className="block">    candidates = [i for c in order for i in lists[c]]</span>
            <span className="block">    best = sorted(candidates, key=lambda i: dist2(q, vectors[i]))[:k]</span>
            <span className="block">    return best, K + len(candidates)</span>
            <span className="block">&nbsp;</span>
            <span className="block">queries = []</span>
            <span className="block">for i in range(50):</span>
            <span className="block">    c = centers[random.randrange(K)]</span>
            <span className="block">    queries.append([x + (random.random() - 0.5) * 0.3 for x in c])</span>
            <span className="block">&nbsp;</span>
            <span className="block">print(&quot;Vectors:&quot;, N, &quot;| lists:&quot;, K, &quot;| exact search checks&quot;, N, &quot;vectors per query&quot;)</span>
            <span className="block">for nprobe in (1, 2, 4, 8):</span>
            <span className="block">    recalls = []</span>
            <span className="block">    work = []</span>
            <span className="block">    for q in queries:</span>
            <span className="block">        truth = set(exact_search(q, 5))</span>
            <span className="block">        found, cost = ivf_search(q, 5, nprobe)</span>
