Documents are written the opposite way: formal and complete. <strong className="text-white">Query transformation</strong> closes that gap by improving the question before retrieval. Even a perfect retriever cannot find what the query fails to describe.</div>

    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Compare what people type with what the documents say.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">

            <tr><td className="px-4 py-3 font-semibold text-white">holiday allowance</td><td className="px-4 py-3">vacation policy</td><td className="px-4 py-3">Different word for the same idea</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">And for the Pro one?</td><td className="px-4 py-3">The Pro plan costs 25 dollars</td><td className="px-4 py-3">Meaning depends on the previous message</td></tr>

  <section>
    <h2 className="mb-6 border-l-4 border-violet-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">2. Beginner: Normalization and Rewriting</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div><strong className="text-white">Query normalization</strong> cleans and standardizes the text: fixing case and spacing, correcting obvious typos, and expanding abbreviations into the words the documents use. It is cheap and often done with simple rules or a lookup table.</div>
      <div><strong className="text-white">Query rewriting</strong> goes further and rewrites the whole question so it can stand alone. In a conversation the latest message is often incomplete, so the system uses the chat history to produce a self-contained version.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-slate-200">
            <tr><th className="px-4 py-3">Latest message</th><th className="px-4 py-3">Rewritten standalone question</th></tr>
          </thead>
          <tbody className="divide-y divide-white/10">
            <tr><td className="px-4 py-3 font-semibold text-white">And for the Pro one?</td><td className="px-4 py-3">What is the price of the Pro plan?</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Does it work offline?</td><td className="px-4 py-3">Does the mobile app work without an internet connection?</td></tr>
          </tbody>
        </table>
      </div>
      <div className="rounded-xl border border-violet-500/20 bg-violet-500/[0.05] p-5"><strong className="text-violet-300">Do not skip this in chatbots:</strong> a follow-up like what about the second one is meaningless to a retriever. Without rewriting, multi-turn assistants retrieve poorly after the first message.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Intermediate: Query Expansion</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div><strong className="text-white">Query expansion</strong> adds related words to the query so more relevant documents can match: synonyms, alternate spellings, related terms and abbreviations with their long forms.</div>
      <div className="grid gap-5 md:grid-cols-3">
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Where it helps most</div>
          <div className="text-sm leading-7">Keyword and hybrid search, where documents must contain the query words to match.</div>
        </div>
        <div className="rounded-xl border border-amber-500/25 bg-amber-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-amber-300">Where it helps less</div>
          <div className="text-sm leading-7">Dense retrieval, which already matches meaning, though expansion can still add missing context.</div>
        </div>
        <div className="rounded-xl border border-rose-500/25 bg-rose-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-rose-300">The danger</div>
          <div className="text-sm leading-7">Query drift: too many added terms pull the search toward a different topic.</div>
        </div>
      </div>
      <div>A safe pattern keeps the original query and adds expansions with lower weight, or runs them as separate searches. Never replace the user wording without a measured reason.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: Multi-Query Retrieval</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>In <strong className="text-white">multi-query retrieval</strong> the system produces several versions of the question, often with a language model, runs a search for each, and merges the results. Different phrasings reach different chunks, so the union has higher recall than any single search.</div>
      <div className="space-y-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">1.</strong> Generate 3 to 5 variants: rephrased, more formal, with synonyms.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">2.</strong> Always include the original question.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">3.</strong> Search with every variant.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">4.</strong> Merge by removing duplicates, or by fusing the rankings with reciprocal rank fusion.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">5.</strong> Pass the merged list to the reranker.</div>
      </div>
      <div className="rounded-xl border border-orange-500/20 bg-orange-500/[0.05] p-5"><strong className="text-orange-300">Cost:</strong> every variant is another search, and generating variants may add a model call. Latency and expense multiply, so use it where recall problems are proven.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">5. Advanced: Decomposition, Routing and Quality Control</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div><strong className="text-white">Query decomposition</strong> splits a compound question into simple ones that are each searched separately, and the results are combined. A question such as WFH rules and 2FA setup becomes two focused queries, each of which finds its own policy. A single embedding of the combined text would point somewhere in between and may find neither.</div>
      <div>Related ideas include <strong className="text-white">routing</strong> a query to the right index or tool, and deciding that no transformation is needed. Simple, clear questions should pass through untouched.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-slate-200">

          </thead>
          <tbody className="divide-y divide-white/10">
            <tr><td className="px-4 py-3 font-semibold text-white">Normalization</td><td className="px-4 py-3">Consistent wording</td><td className="px-4 py-3">Almost free</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Rewriting</td><td className="px-4 py-3">Standalone meaning</td><td className="px-4 py-3">One model call</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Expansion</td><td className="px-4 py-3">Extra vocabulary</td><td className="px-4 py-3">Light, or one model call</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Multi-query</td><td className="px-4 py-3">Higher recall</td><td className="px-4 py-3">Several searches</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Decomposition</td><td className="px-4 py-3">Coverage of compound questions</td><td className="px-4 py-3">Several searches plus merging</td></tr>
          </tbody>
        </table>
      </div>
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5"><strong className="text-cyan-300">Prove each step:</strong> measure retrieval quality with and without every transformation on your test questions, and keep only those that help. Log the original and the transformed queries so you can debug surprising results.</div>
    </div>
  </section>

    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">7. Python Implementation: Normalize, Merge Variants and Decompose</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The program searches four short policy documents with a simple word-match retriever. Each query is searched as typed, and then again after normalization, where abbreviations and synonyms are replaced with the words the documents use. Results from the original and the normalized query are merged, as in multi-query retrieval. The last lines split a compound question into two sub-queries and search each one.</div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3"><span className="font-mono text-xs font-semibold text-teal-400">query_transform.py</span><span className="font-mono text-[11px] text-slate-400">Python 3.10+ · Standard library only</span></div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">rewrites = dict([(&quot;pto&quot;, &quot;paid time off&quot;), (&quot;wfh&quot;, &quot;work from home&quot;), (&quot;2fa&quot;, &quot;two factor authentication&quot;), (&quot;holiday&quot;, &quot;vacation&quot;)])</span>
            <span className="block">stop_words = set([&quot;how&quot;, &quot;many&quot;, &quot;do&quot;, &quot;i&quot;, &quot;get&quot;, &quot;a&quot;, &quot;the&quot;, &quot;what&quot;, &quot;is&quot;, &quot;my&quot;, &quot;of&quot;, &quot;and&quot;, &quot;for&quot;, &quot;to&quot;, &quot;can&quot;, &quot;does&quot;])</span>
            <span className="block">&nbsp;</span>
            <span className="block">documents = [</span>
            <span className="block">    (&quot;d1&quot;, &quot;vacation policy employees receive 20 days of paid time off per year&quot;),</span>
            <span className="block">    (&quot;d2&quot;, &quot;work from home policy remote work is allowed two days per week&quot;),</span>
            <span className="block">    (&quot;d3&quot;, &quot;security policy enable two factor authentication on every account&quot;),</span>
            <span className="block">    (&quot;d4&quot;, &quot;expense policy submit receipts within 30 days&quot;),</span>
            <span className="block">]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def words(text):</span>
            <span className="block">    return &quot;&quot;.join(ch if ch.isalnum() or ch == &quot; &quot; else &quot; &quot; for ch in text.lower()).split()</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def normalize(query):</span>
            <span className="block">    return &quot; &quot;.join(rewrites.get(w, w) for w in words(query))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def search(query, k=2):</span>
            <span className="block">    q = set(w for w in words(query) if w not in stop_words)</span>
            <span className="block">    scored = [(len(q &amp; set(words(text))), doc_id) for doc_id, text in documents]</span>
            <span className="block">    scored.sort(key=lambda s: (-s[0], s[1]))</span>
            <span className="block">    return [doc_id for score, doc_id in scored[:k] if score &gt; 0]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def multi_query(query):</span>
            <span className="block">    variants = [query, normalize(query)]</span>
            <span className="block">    seen = []</span>
            <span className="block">    for variant in variants:</span>
            <span className="block">        for doc_id in search(variant):</span>
            <span className="block">            if doc_id not in seen:</span>
            <span className="block">                seen.append(doc_id)</span>
            <span className="block">    return variants, seen</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def decompose(query):</span>
            <span className="block">    parts = query.lower().split(&quot; and &quot;)</span>
            <span className="block">    return [p.strip() for p in parts]</span>
            <span className="block">&nbsp;</span>
            <span className="block">for query in [&quot;How much PTO do I get?&quot;, &quot;holiday allowance for staff&quot;, &quot;WFH rules and 2FA setup&quot;]:</span>
            <span className="block">    variants, merged = multi_query(query)</span>
            <span className="block">    print(&quot;Query:&quot;, query)</span>
            <span className="block">    print(&quot;  Original search :&quot;, search(query))</span>
            <span className="block">    print(&quot;  Normalized text :&quot;, normalize(query))</span>
            <span className="block">    print(&quot;  Multi-query merge:&quot;, merged)</span>
            <span className="block">&nbsp;</span>
            <span className="block">print(&quot;&quot;)</span>
            <span className="block">parts = decompose(&quot;WFH rules and 2FA setup&quot;)</span>
            <span className="block">print(&quot;Decomposed into:&quot;, parts)</span>
            <span className="block">combined = []</span>
            <span className="block">for part in parts:</span>
            <span className="block">    for doc_id in search(normalize(part), k=1):</span>
            <span className="block">        combined.append(doc_id)</span>
            <span className="block">print(&quot;One search per sub-question:&quot;, combined)</span>
