  <section>
    <h2 className="mb-6 border-l-4 border-blue-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">1. Intermediate: From Pipelines to Agents</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>In a pipeline, the developer fixes the steps. In an <strong className="text-white">agent</strong>, the model chooses the next step at run time by repeating a simple loop: <strong className="text-white">plan</strong> what is needed, <strong className="text-white">act</strong> by calling a tool, <strong className="text-white">observe</strong> the result, and <strong className="text-white">decide</strong> whether to continue or answer.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-slate-200">
            <tr><th className="px-4 py-3">Aspect</th><th className="px-4 py-3">Fixed pipeline</th><th className="px-4 py-3">Agentic RAG</th></tr>
          </thead>
          <tbody className="divide-y divide-white/10">
            <tr><td className="px-4 py-3 font-semibold text-white">Who chooses the steps</td><td className="px-4 py-3">The developer</td><td className="px-4 py-3">The model, step by step</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Handles unexpected question types</td><td className="px-4 py-3 text-rose-300">Poorly</td><td className="px-4 py-3 text-emerald-300">Better</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Predictability, cost, latency</td><td className="px-4 py-3 text-emerald-300">High</td><td className="px-4 py-3 text-rose-300">Lower, varies by question</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Debugging</td><td className="px-4 py-3 text-emerald-300">Simple</td><td className="px-4 py-3 text-amber-300">Needs full traces of every step</td></tr>
          </tbody>
        </table>
      </div>
      <div className="rounded-xl border border-blue-500/20 bg-blue-500/[0.05] p-5"><strong className="text-blue-300">Rule of thumb:</strong> use a fixed pipeline whenever it solves the problem, and use an agent only for questions whose steps cannot be known in advance.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-violet-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">2. Intermediate: Agent Patterns for Retrieval</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-violet-300">Planning plus retrieval</div>
          <div className="text-sm leading-7">The agent first breaks the task into steps, then retrieves for each, and revises the plan when results surprise it.</div>
        </div>
        <div className="rounded-xl border border-blue-500/25 bg-blue-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-blue-300">Tool-based retrieval</div>
          <div className="text-sm leading-7">Search, SQL, calculators, web search and APIs are all tools. The agent picks the right one for each sub-question.</div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Iterative retrieval</div>
          <div className="text-sm leading-7">The agent reads, notices what is missing, and searches again with a better query until the evidence is sufficient.</div>
        </div>
        <div className="rounded-xl border border-orange-500/25 bg-orange-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-orange-300">Multi-step reasoning workflows</div>
          <div className="text-sm leading-7">Several steps with intermediate results, such as finding a price and then computing a yearly total.</div>
        </div>
      </div>
      <div>Agents bring risks that fixed pipelines avoid. Errors compound across steps, loops can run without end, costs are unpredictable, and every tool and every retrieved document is a new path for prompt injection to cause real actions.</div>
      <div className="space-y-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-violet-300">Cap</strong> the number of steps, tool calls and total cost per request.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-violet-300">Restrict</strong> tools to the minimum, with read-only access by default.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-violet-300">Approve</strong> sensitive actions with a human.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-violet-300">Trace</strong> every thought, call and result.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-violet-300">Evaluate</strong> whole trajectories, not just the final answer.</div>
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">3. Intermediate: Fine-Tuning Retrieval and Embeddings</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Off-the-shelf embedding models are general. If your domain has special vocabulary, such as legal, medical or internal product language, <strong className="text-white">fine-tuning</strong> the retriever or the embedding model on your own examples can raise retrieval quality noticeably.</div>
      <div className="space-y-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Collect</strong> pairs of questions and the passages that answer them, from logs, experts or carefully reviewed synthetic data.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Add hard negatives</strong> passages that look relevant but are not, so the model learns to tell them apart.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Train</strong> with a contrastive objective that pulls matching pairs together and pushes others apart.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Compare</strong> against the original model on a held-out golden set.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-emerald-300">Re-embed</strong> the whole index with the new model, since vectors from different models cannot be mixed.</div>
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5"><strong className="text-emerald-300">Try the cheaper things first:</strong> better chunking, hybrid search and reranking often give comparable gains without training. Fine-tune when evaluation shows that the embedding model itself is the bottleneck, and you have enough good data.</div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: ColBERT, Late Interaction and Learned Sparse Retrieval</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>Standard dense retrieval compresses a whole passage into one vector. <strong className="text-white">ColBERT</strong>, a late-interaction model, keeps <strong className="text-white">one vector per token</strong> and compares query and document tokens at search time. The score sums, for each query token, its best match among the document tokens, an operation called <strong className="text-white">MaxSim</strong>:</div>
      <div className="overflow-x-auto rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">$$S(q,d) = \sum_{i \in q} \max_{j \in d} \; q_i \cdot d_j$$</div>
      <div>This keeps fine-grained detail that a single vector blurs, at the price of storing many more vectors per document. It is often used to rerank or to retrieve with specialized indexes.</div>
      <div><strong className="text-white">Learned sparse retrieval</strong> goes the other direction. A model learns which words matter and which related words to add, and produces sparse weighted vectors. They keep the inverted-index machinery and exact-match strengths of keyword search, with some semantic reach added.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-slate-200">
            <tr><th className="px-4 py-3">Approach</th><th className="px-4 py-3">Representation</th><th className="px-4 py-3">Strength</th><th className="px-4 py-3">Cost</th></tr>
          </thead>
          <tbody className="divide-y divide-white/10">
            <tr><td className="px-4 py-3 font-semibold text-white">Single-vector dense</td><td className="px-4 py-3">One vector per passage</td><td className="px-4 py-3">Simple, fast, small</td><td className="px-4 py-3">Blurs fine detail</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Late interaction (ColBERT)</td><td className="px-4 py-3">One vector per token</td><td className="px-4 py-3">Fine-grained matching</td><td className="px-4 py-3">Much more storage</td></tr>
            <tr><td className="px-4 py-3 font-semibold text-white">Learned sparse</td><td className="px-4 py-3">Weighted words with expansions</td><td className="px-4 py-3">Exact terms plus some meaning, uses inverted indexes</td><td className="px-4 py-3">Needs a trained model</td></tr>
          </tbody>
        </table>
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">5. Advanced: Research Directions</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The field moves fast. These themes are active, and each deserves a measured, evidence-first attitude.</div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-cyan-500/25 bg-cyan-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-cyan-300">Retrieval-augmented pretraining</div>
          <div className="text-sm leading-7">Training language models with a retriever in the loop, so knowledge lives partly in an external store from the start. Research such as REALM and RETRO explored this.</div>
        </div>
        <div className="rounded-xl border border-blue-500/25 bg-blue-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-blue-300">RAG plus fine-tuning</div>
          <div className="text-sm leading-7">Fine-tune the generator to use retrieved context faithfully and to ignore irrelevant passages, while retrieval supplies the facts.</div>
        </div>
        <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-violet-300">Long context versus RAG</div>
          <div className="text-sm leading-7">Larger windows do not make retrieval obsolete: cost, latency, control and reliability still favor selecting the right text. Expect the two to be combined.</div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Self-improving RAG</div>
          <div className="text-sm leading-7">Systems that learn from feedback, such as clicks and corrections, by updating queries, indexes or models. Promising, but needs safeguards against learning the wrong lessons.</div>
        </div>
      </div>
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5"><strong className="text-cyan-300">How to stay sane:</strong> for any new technique, ask what failure of your current system it addresses, test it on your golden dataset, and measure quality, cost and latency together. Many ideas look strong on a paper benchmark and add little to a well-tuned simple system.</div>
    </div>
  </section>

    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">7. Python Implementation: A Tiny Tool-Using Agent and MaxSim Scoring</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The first half is a minimal agent with two tools, search and multiply, and a step limit. The decision rule is written by hand so the program is deterministic, while a real agent would let a language model choose each action. It answers what the Pro plan costs for a year by searching for the monthly price, then multiplying it by 12. The second half scores two candidate passages for a query with MaxSim, using a tiny hand-made table of token vectors in place of a trained model.</div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3"><span className="font-mono text-xs font-semibold text-teal-400">agent_and_maxsim.py</span><span className="font-mono text-[11px] text-slate-400">Python 3.10+ · Standard library only</span></div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">import math</span>
            <span className="block">&nbsp;</span>
            <span className="block">docs = [</span>
            <span className="block">    &quot;Pro plan costs 25 dollars per month.&quot;,</span>
            <span className="block">    &quot;Basic plan costs 10 dollars per month.&quot;,</span>
            <span className="block">]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def search(query):</span>
            <span className="block">    q = set(w for w in query.lower().replace(&quot;?&quot;, &quot;&quot;).split() if len(w) &gt; 2)</span>
            <span className="block">    return max(docs, key=lambda d: len(q &amp; set(d.lower().replace(&quot;.&quot;, &quot;&quot;).split())))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def find_number(text):</span>
            <span className="block">    for word in text.split():</span>
            <span className="block">        if word.isdigit():</span>
            <span className="block">            return int(word)</span>
            <span className="block">    return None</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def multiply(a, b):</span>
            <span className="block">    return a * b</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def agent(question, max_steps=4):</span>
            <span className="block">    price = None</span>
            <span className="block">    trace = []</span>
            <span className="block">    for step in range(1, max_steps + 1):</span>
            <span className="block">        if price is None:</span>
            <span className="block">            result = search(&quot;pro plan costs month&quot;)</span>
            <span className="block">            price = find_number(result)</span>
            <span className="block">            trace.append(&quot;step &quot; + str(step) + &quot;: search -&gt; &quot; + result)</span>
            <span className="block">        else:</span>
            <span className="block">            total = multiply(price, 12)</span>
            <span className="block">            trace.append(&quot;step &quot; + str(step) + &quot;: multiply &quot; + str(price) + &quot; x 12 = &quot; + str(total))</span>
            <span className="block">            trace.append(&quot;step &quot; + str(step + 1) + &quot;: finish&quot;)</span>
            <span className="block">            return total, trace</span>
            <span className="block">    return None, trace</span>
            <span className="block">&nbsp;</span>
            <span className="block">total, trace = agent(&quot;What does the Pro plan cost for a year?&quot;)</span>
            <span className="block">for line in trace:</span>
