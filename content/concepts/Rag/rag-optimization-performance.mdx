    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The fastest request is the one you never repeat. Caches store results that are expensive to compute and likely to be needed again.</div>
      <div className="grid gap-5 md:grid-cols-3">
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-emerald-300">Embedding cache</div>
          <div className="text-sm leading-7">Store the vector for each normalized query, so repeated questions skip the embedding call.</div>
        </div>
        <div className="rounded-xl border border-blue-500/25 bg-blue-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-blue-300">Retrieval cache</div>
          <div className="text-sm leading-7">Store the retrieved chunk ids for a query, valid until the index changes.</div>
        </div>
        <div className="rounded-xl border border-orange-500/25 bg-orange-500/[0.04] p-5">
          <div className="mb-2 font-semibold text-orange-300">Semantic cache</div>
          <div className="text-sm leading-7">Reuse a stored answer when a new question is very similar to an earlier one. Large savings, but a wrong match returns a wrong answer.</div>
        </div>
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5"><strong className="text-emerald-300">Cache safely:</strong> invalidate cached answers when their source documents change, and include user permissions in the cache key, otherwise one user may receive an answer built from documents another user is allowed to see. Normalizing queries first, such as lowercasing and removing punctuation, raises the hit rate.</div>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">4. Intermediate: Latency and Throughput</h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div><strong className="text-white">Latency</strong> is how long one request takes. <strong className="text-white">Throughput</strong> is how many requests the system completes per second. They are related by a simple rule of queues: the number of requests in progress at once equals the arrival rate times the time each takes.</div>
      <div className="overflow-x-auto rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">$$\text{concurrent requests} = \text{requests per second} \times \text{seconds per request}$$</div>
      <div>At 20 requests per second and 1.5 seconds per request, about 30 requests are in flight at any moment, so slower requests need more capacity. Track latency by percentile, such as p50 and p95, not by average. A p95 of 4 seconds means one user in twenty waits that long, even if the average looks fine.</div>
      <div className="space-y-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">Parallelize</strong> independent work, for example dense and sparse search at the same time.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">Reduce candidates</strong> sent to the reranker, since its time grows with their number.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">Stream</strong> the answer as it is generated so the user sees the first words early.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">Use smaller models</strong> for routing and grading steps.</div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-4"><strong className="text-orange-300">Batch</strong> embedding work during ingestion.</div>
      </div>

    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>The program builds three small models. First, an embedding cache keyed by a normalized query shows how spelling and punctuation differences are absorbed. Second, a latency model adds the time of each stage, with reranking proportional to the candidate count, and compares two configurations. Third, a cost model converts chunk count and chunk size into prompt tokens and into a monthly total. The timings and prices are illustrative, not measurements of any real system.</div>

        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">

            <span className="block text-cyan-300">def normalize(query):</span>
            <span className="block">    return &quot; &quot;.join(&quot;&quot;.join(ch for ch in query.lower() if ch.isalnum() or ch == &quot; &quot;).split())</span>
            <span className="block">&nbsp;</span>
            <span className="block">cache = dict()</span>
            <span className="block">stats = [0, 0]</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def embed_cached(query):</span>
            <span className="block">    key = normalize(query)</span>
            <span className="block">    if key in cache:</span>
            <span className="block">        stats[0] += 1</span>
            <span className="block">        return &quot;hit&quot;</span>
            <span className="block">    cache[key] = True</span>
            <span className="block">    stats[1] += 1</span>
            <span className="block">    return &quot;miss&quot;</span>
            <span className="block">&nbsp;</span>

            <span className="block">    generate = 600</span>
