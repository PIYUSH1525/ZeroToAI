    <h2 className="mb-6 border-l-4 border-blue-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      1. Beginner: What Is a Context Window?
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        The <strong className="text-white">context window</strong> is the maximum amount of text, measured in <strong className="text-white">tokens</strong>, that a model can look at in one go. It is the model&apos;s working memory. Everything has to fit inside it: your system instructions, the whole conversation so far, any documents you paste in, <strong className="text-white">and</strong> the answer the model is about to write.
      </div>
      <div>
        A token is a piece of a word. A rough rule for English is that <strong className="text-white">1 token is about 0.75 words</strong>, so a 100,000-token window is roughly 75,000 words, about the length of a short novel.
      </div>
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-cyan-300">Key point:</strong> The window is shared. If your prompt uses 7,000 tokens of an 8,000-token window, the answer can be at most about 1,000 tokens long.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      4. Medium: The KV Cache and Prompt Caching
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        As you saw in the attention lesson, a model stores the keys and values of earlier tokens in a <strong className="text-white">KV cache</strong> so it does not recompute them. That cache lives in GPU memory and grows with every token of every active conversation.
      </div>
      <div className="rounded-xl border border-white/10 bg-[#060913] p-5 text-center text-white">
        $$\text{cache memory} = 2 \times \text{layers} \times \text{KV heads} \times \text{head size} \times \text{tokens} \times \text{bytes}$$
      </div>
      <div>
        <strong className="text-white">Prompt caching</strong> is a related service feature. If many requests start with the <em>same long prefix</em> (a big system prompt, a document, a set of examples), the provider can reuse the already-computed cache for that prefix. Cached input tokens are usually billed at a discount and are faster.
      </div>
      <div className="rounded-xl border border-blue-500/20 bg-blue-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-blue-300">Design tip:</strong> Put the <strong className="text-white">stable</strong> part of your prompt first and the <strong className="text-white">changing</strong> part last. Then repeated requests share the same prefix and can hit the cache.
      </div>
    </div>
  </section>
