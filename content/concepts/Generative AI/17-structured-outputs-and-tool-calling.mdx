      1. Beginner: Why Free Text Is Not Enough
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        A chat answer written for a human is easy to read but hard for a program to use. Imagine your app asks a model to classify a review and the model replies <em>Sure! I think this one is positive, probably.</em> Your code cannot reliably pull the label out of that sentence.
      </div>
      <div>
        <strong className="text-white">Structured outputs</strong> solve this by making the model reply in a fixed format, usually <strong className="text-white">JSON</strong> that follows a schema you define. <strong className="text-white">Tool calling</strong> goes one step further: the model can ask your program to <em>do</em> something, such as look up the weather or query a database.
      </div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-rose-500/25 bg-rose-500/[0.04] p-6">

            <span className="font-bold text-rose-300">Free text</span>
            <span className="rounded bg-rose-950/80 px-2 py-0.5 font-mono text-xs text-rose-300">Hard to parse</span>
          </div>
          <div className="mt-2 space-y-2 text-xs leading-relaxed text-slate-300">
            <div><strong className="text-white">Reply:</strong> <em>Sure! It seems positive.</em></div>
            <div><strong className="text-white">Problem:</strong> Your code must guess where the answer is.</div>
          </div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-6">
          <div className="mb-1 flex items-center justify-between">
            <span className="font-bold text-emerald-300">Structured</span>
            <span className="rounded bg-emerald-950/80 px-2 py-0.5 font-mono text-xs text-emerald-300">Easy to parse</span>
          </div>

            <tr><td className="px-5 py-3 font-semibold text-white">tags</td><td className="px-5 py-3">list of strings</td><td className="px-5 py-3">Topics mentioned in the review</td></tr>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      3. Medium: How Constrained Decoding Works
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Schema-constrained output does not rely on the model <em>choosing</em> to behave. At every step the system looks at the format rules and <strong className="text-white">blocks every token that would break them</strong>, by setting its probability to zero before sampling. If the schema says the next character must be a quote or a digit, no other token can be chosen.
      </div>
      <div className="space-y-3">
        <div className="flex items-start gap-4 rounded-xl border border-blue-500/20 bg-blue-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-blue-500/20 font-mono text-sm font-bold text-blue-300">1</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Model scores tokens:</strong> As usual, it scores every token in the vocabulary.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-violet-500/20 bg-violet-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-violet-500/20 font-mono text-sm font-bold text-violet-300">2</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Grammar filter:</strong> Tokens that would break the schema are removed.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-emerald-500/20 bg-emerald-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-emerald-500/20 font-mono text-sm font-bold text-emerald-300">3</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Sample from what is left:</strong> Only valid tokens remain, so the result is always well-formed.</div>

        <strong className="text-amber-300">Important:</strong> A valid <strong className="text-white">format</strong> does not mean a <strong className="text-white">correct</strong> answer. The JSON can be perfectly shaped and still wrong. Always check the content, not only the shape.
      </div>
    </div>

    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">

The model never runs anything itself. It only replies with <em>which tool to call and with what arguments</em>. Your program runs the tool and sends the result back.
      </div>
      <div className="space-y-3">
        <div className="flex items-start gap-4 rounded-xl border border-blue-500/20 bg-blue-500/[0.04] p-4">

        </div>
        <div className="flex items-start gap-4 rounded-xl border border-violet-500/20 bg-violet-500/[0.04] p-4">

        </div>

      5. Advanced: Safety, Validation and Failure Handling
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Anything the model returns is <strong className="text-white">untrusted input</strong>, just like text typed by a stranger. Treat tool calls with the same care as a public web form:
      </div>
      <div className="overflow-x-auto rounded-2xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-xs uppercase tracking-wider text-slate-400">
            <tr>
              <th className="px-5 py-3">Risk</th>
              <th className="px-5 py-3">Defense</th>
            </tr>
          </thead>
          <tbody className="divide-y divide-white/5 text-slate-300">
            <tr><td className="px-5 py-3 font-semibold text-white">Invalid or missing fields</td><td className="px-5 py-3">Validate every response against the schema and retry or repair on failure</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Wrong or dangerous arguments</td><td className="px-5 py-3">Check values (ranges, allowed lists) before running the tool</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Too much power</td><td className="px-5 py-3">Give each tool the minimum permission it needs. Prefer read-only tools</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Prompt injection through tool results</td><td className="px-5 py-3">Web pages or emails can contain hidden instructions. Treat tool output as data, never as commands</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Irreversible actions</td><td className="px-5 py-3">Ask the human to confirm before sending money, deleting data or emailing people</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Endless loops</td><td className="px-5 py-3">Limit the number of tool calls per request</td></tr>
          </tbody>
        </table>

        <div className="text-sm leading-relaxed text-slate-300">Some models can ask for several independent tools at once, for example the weather in two cities. Your code can run them together and return all the results in one go.</div>
      </div>
    </div>
