    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>

            <tr><td className="px-5 py-3 font-semibold text-white">4,000 tokens</td><td className="px-5 py-3">16,000,000</td><td className="px-5 py-3">1×</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">32,000 tokens</td><td className="px-5 py-3">1,024,000,000</td><td className="px-5 py-3">64×</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">128,000 tokens</td><td className="px-5 py-3">16,384,000,000</td><td className="px-5 py-3">1,024×</td></tr>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      3. Medium: FlashAttention, the Same Answer With Less Memory
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        A GPU has a small, very fast on-chip memory and a large, slower main memory. Standard attention writes the whole $n \times n$ score table to the slow memory and reads it back. Most of the time is spent moving data, not calculating.
      </div>
      <div>
        <strong className="text-white">FlashAttention</strong> processes the keys and values in small <strong className="text-white">tiles</strong> that fit in the fast memory and never writes the full table. The difficulty is the softmax, which seems to need all scores at once. The trick is the <strong className="text-white">online softmax</strong>: keep a running maximum and a running sum, and rescale what was accumulated whenever a new tile arrives.
      </div>
      <div className="space-y-3">
        <div className="flex items-start gap-4 rounded-xl border border-blue-500/20 bg-blue-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-blue-500/20 font-mono text-sm font-bold text-blue-300">1</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Load a tile of K and V:</strong> Small enough for fast memory.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-violet-500/20 bg-violet-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-violet-500/20 font-mono text-sm font-bold text-violet-300">2</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Compute scores for that tile:</strong> Only a small block of the table exists.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-emerald-500/20 bg-emerald-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-emerald-500/20 font-mono text-sm font-bold text-emerald-300">3</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Update the running max and sum:</strong> Rescale the earlier partial results.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-orange-500/20 bg-orange-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-orange-500/20 font-mono text-sm font-bold text-orange-300">4</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Add the tile&apos;s contribution to the output:</strong> Then discard the tile and move to the next.</div>
        </div>
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-emerald-300">Result:</strong> Exactly the same output as standard attention, but memory for the score table drops from $n^2$ to a small tile, and speed improves a lot because far less data is moved.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      4. Medium: Sliding Windows and Sparse Patterns
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        <strong className="text-white">Sliding-window attention</strong> limits each token to the previous $w$ tokens (for example 4,096). The cost becomes about $n \times w$ instead of $n^2$, which is linear in length. Information can still travel far, because each layer passes information a window further, so stacked layers see much beyond one window.
      </div>
      <div>
        <strong className="text-white">Sparse</strong> patterns add a few <strong className="text-white">global</strong> tokens (like the start of the text or special markers) that every token can see, so important information is never fully cut off.
      </div>
      <div className="overflow-x-auto rounded-2xl border border-white/10">
        <table className="w-full text-left text-sm">
          <thead className="bg-white/[0.04] text-xs uppercase tracking-wider text-slate-400">
            <tr>
              <th className="px-5 py-3">Method</th>
              <th className="px-5 py-3">Cost for n tokens</th>
              <th className="px-5 py-3">Keeps</th>
            </tr>
          </thead>
          <tbody className="divide-y divide-white/5 text-slate-300">
            <tr><td className="px-5 py-3 font-semibold text-white">Full attention</td><td className="px-5 py-3">about n²</td><td className="px-5 py-3">Everything</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Sliding window (w)</td><td className="px-5 py-3">about n × w</td><td className="px-5 py-3">The most recent w tokens, plus indirect memory through layers</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Local + global</td><td className="px-5 py-3">about n × w + few</td><td className="px-5 py-3">Recent tokens and a few special tokens</td></tr>
          </tbody>
        </table>
      </div>
      <div className="rounded-xl border border-amber-500/20 bg-amber-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-amber-300">Trade-off:</strong> A pure window can forget a detail from early in the document. Models that need exact recall of far-away facts often keep some full-attention layers.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      5. Advanced: Ring Attention, Position Scaling and Beyond
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        When one GPU cannot even hold the KV cache of a very long input, the sequence itself is split. <strong className="text-white">Ring attention</strong> gives each GPU a piece of the sequence. The GPUs pass blocks of keys and values around a ring while each computes its share, so the result is exact and memory per GPU stays small.
      </div>
      <div>
        To make a model handle lengths beyond its training length, it also needs its positions rescaled (see the RoPE lesson) and usually some extra training on long documents.
      </div>
      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="mb-2 font-bold text-white">Architectures beyond attention</div>
        <div className="text-sm leading-relaxed text-slate-300"><strong className="text-white">State-space models</strong> and other linear-time designs keep a fixed-size memory that is updated token by token, so cost grows only linearly with length. They are efficient but can be weaker at exact recall, so some recent models mix them with a few attention layers.</div>
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-emerald-300">Practical advice:</strong> Choose the <strong className="text-white">shortest context that solves your task</strong>. Use retrieval (RAG) to bring in only relevant pieces, and use long-context models when you really need the whole document at once.
      </div>
    </div>
  </section>

  <section>
    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      7. Python Implementation: Window Savings and Online Softmax
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        This script counts how many token pairs full attention and a 4,096-token sliding window need at three lengths, then implements a tiled, FlashAttention-style attention with online softmax and checks that it matches standard attention exactly.
      </div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3">
          <span className="font-mono text-xs font-semibold text-teal-400">efficient_attention.py</span>
          <span className="font-mono text-[11px] text-slate-400">Python 3.10+ · NumPy only</span>
        </div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">import numpy as np</span>
            <span className="block">&nbsp;</span>
            <span className="block text-slate-500"># 1. Sliding-window attention: each token looks only at the last &#96;window&#96; tokens</span>
            <span className="block text-cyan-300">def pairs&#95;full(n):</span>
            <span className="block">    return n &#42; (n + 1) // 2                              # causal: every token sees all earlier tokens</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def pairs&#95;window(n, window):</span>
            <span className="block">    return sum(min(i + 1, window) for i in range(n))</span>
            <span className="block">&nbsp;</span>
            <span className="block">for n in &#91;4096, 32768, 131072&#93;:</span>
            <span className="block">    full, win = pairs&#95;full(n), pairs&#95;window(n, 4096)</span>
            <span className="block">    print(&quot;n =&quot;, format(n, &quot;,&quot;), &quot;| full:&quot;, format(full, &quot;,&quot;), &quot;| window 4096:&quot;, format(win, &quot;,&quot;), &quot;| saving:&quot;, round(full / win, 1), &quot;x&quot;)</span>
            <span className="block">&nbsp;</span>
            <span className="block text-slate-500"># 2. Online softmax: the trick inside FlashAttention (process scores in small tiles)</span>
            <span className="block">rng = np.random.default&#95;rng(0)</span>
            <span className="block">n, d, tile = 64, 16, 16</span>
            <span className="block">Q, K, V = rng.normal(size=(3, n, d))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def standard&#95;attention(Q, K, V):</span>
            <span className="block">    S = Q @ K.T / np.sqrt(d)</span>
            <span className="block">    P = np.exp(S - S.max(axis=1, keepdims=True))</span>
            <span className="block">    return (P / P.sum(axis=1, keepdims=True)) @ V</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def tiled&#95;attention(Q, K, V):</span>
            <span className="block">    m = np.full(n, -np.inf)                              # running max of scores</span>
            <span className="block">    l = np.zeros(n)                                      # running sum of exponentials</span>
            <span className="block">    out = np.zeros((n, d))</span>
            <span className="block">    for start in range(0, n, tile):                      # one tile of keys and values at a time</span>
