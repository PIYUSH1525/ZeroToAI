  <section>
    <h2 className="mb-6 border-l-4 border-blue-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      1. Beginner: Why Memory Is the First Question
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Before asking <em>how smart is this model?</em>, practitioners ask <em>will it even fit on my GPU?</em> A model is just billions of numbers (<strong className="text-white">parameters</strong>), and every number must live in the GPU&apos;s fast memory, called <strong className="text-white">VRAM</strong>, while the model runs.
      </div>
      <div className="rounded-xl border border-white/10 bg-[#060913] p-5 text-center text-white">
        $$\text{memory for weights} = \text{number of parameters} \times \text{bytes per parameter}$$
      </div>
      <div>
        So a model with 7 billion parameters needs 7 billion times the size of one number. How big one number is depends on its <strong className="text-white">precision</strong>.
      </div>
      <div className="rounded-xl border border-cyan-500/20 bg-cyan-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-cyan-300">Analogy:</strong> Think of a photo album. Each photo is a parameter. A high-resolution print takes more shelf space than a thumbnail. Lowering precision is like storing thumbnails: you can fit many more photos, but each loses some detail.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-violet-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      2. Beginner: Number Formats (Precision)
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div className="overflow-x-auto rounded-2xl border border-white/10">
        <table className="w-full text-left text-sm">

          </thead>
          <tbody className="divide-y divide-white/5 text-slate-300">
            <tr><td className="px-5 py-3 font-semibold text-white">float32 (FP32)</td><td className="px-5 py-3">32</td><td className="px-5 py-3">4</td><td className="px-5 py-3">28 GB</td><td className="px-5 py-3">Older training, scientific work</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">float16 / bfloat16</td><td className="px-5 py-3">16</td><td className="px-5 py-3">2</td><td className="px-5 py-3">14 GB</td><td className="px-5 py-3">Standard for training and inference</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">int8</td><td className="px-5 py-3">8</td><td className="px-5 py-3">1</td><td className="px-5 py-3">7 GB</td><td className="px-5 py-3">Quantized inference</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">int4</td><td className="px-5 py-3">4</td><td className="px-5 py-3">0.5</td><td className="px-5 py-3">3.5 GB</td><td className="px-5 py-3">Aggressive quantization, local models</td></tr>
          </tbody>
        </table>
      </div>
      <div>
        <strong className="text-white">bfloat16</strong> keeps the same <em>range</em> as float32 (so training rarely overflows) but with less <em>precision</em>, which is why it became the favorite for deep learning. <strong className="text-white">float16</strong> has more precision but a smaller range.
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-emerald-300">Easy mental math:</strong> Weights in gigabytes ≈ parameters in billions × bytes per number. A 13B model in 16-bit is about 26 GB.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-emerald-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      3. Medium: What Else Uses Memory?
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Weights are only part of the story. Running a model also needs:
      </div>
      <div className="overflow-x-auto rounded-2xl border border-white/10">

        <strong className="text-white">Training</strong> needs far more than inference. With the common Adam optimizer in mixed precision, each parameter needs about <strong className="text-white">16 bytes</strong>: 2 for the weights, 2 for the gradient, 4 for a 32-bit master copy and 8 for the two optimizer states. A 7B model therefore needs about 112 GB to train fully, versus 14 GB to run.
      </div>
      <div className="rounded-xl border border-amber-500/20 bg-amber-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-amber-300">Rule of thumb for inference:</strong> Plan for weights × 1.2, plus the KV cache for your longest conversations.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      4. Medium: Quantization, Shrinking the Numbers
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        <strong className="text-white">Quantization</strong> stores weights with fewer bits. Instead of a precise decimal like 0.7312, we keep a small integer and one shared <strong className="text-white">scale</strong> number, then multiply to recover an approximation:
      </div>
      <div className="rounded-xl border border-white/10 bg-[#060913] p-5 text-center text-white">
        $$w \approx q \times s \qquad q = \text{round}(w / s)$$
      </div>
      <div className="space-y-3">
        <div className="flex items-start gap-4 rounded-xl border border-blue-500/20 bg-blue-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-blue-500/20 font-mono text-sm font-bold text-blue-300">1</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Find the scale:</strong> Divide the largest absolute weight by the biggest integer the format can hold (127 for int8, 7 for int4).</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-violet-500/20 bg-violet-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-violet-500/20 font-mono text-sm font-bold text-violet-300">2</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Round:</strong> Convert every weight to the nearest integer.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-emerald-500/20 bg-emerald-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-emerald-500/20 font-mono text-sm font-bold text-emerald-300">3</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Store:</strong> Save the small integers and the scale. This is the shrunken model.</div>
        </div>
        <div className="flex items-start gap-4 rounded-xl border border-orange-500/20 bg-orange-500/[0.04] p-4">
          <span className="flex h-8 w-8 shrink-0 items-center justify-center rounded-full bg-orange-500/20 font-mono text-sm font-bold text-orange-300">4</span>
          <div className="text-sm leading-relaxed"><strong className="text-white">Dequantize on the fly:</strong> During the calculation, multiply back by the scale.</div>
        </div>
      </div>
      <div className="rounded-xl border border-emerald-500/20 bg-emerald-500/[0.05] p-5 text-sm leading-relaxed">
        <strong className="text-emerald-300">Why it works:</strong> Neural network weights are noisy and redundant. A small rounding error in each weight usually changes the output very little, so quality drops only slightly.
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      5. Advanced: Group-Wise Methods and the Quality Trade-Off
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        A single scale for a whole matrix is crude: one huge weight forces a coarse scale on everyone. <strong className="text-white">Group-wise quantization</strong> uses a separate scale for each small group (for example 64 or 128 weights), which fits the values much better and is used by most 4-bit methods.
      </div>
      <div className="overflow-x-auto rounded-2xl border border-white/10">

            <tr><td className="px-5 py-3 font-semibold text-white">4-bit NormalFloat (NF4)</td><td className="px-5 py-3">A 4-bit format designed for bell-shaped weights</td><td className="px-5 py-3">QLoRA fine-tuning</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">Quantization-aware training</td><td className="px-5 py-3">Train while simulating the rounding</td><td className="px-5 py-3">Best quality, higher cost</td></tr>
            <tr><td className="px-5 py-3 font-semibold text-white">KV-cache quantization</td><td className="px-5 py-3">Compress the cache, not the weights</td><td className="px-5 py-3">Long-context serving</td></tr>
          </tbody>
        </table>

      <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5">
        <div className="mb-2 font-bold text-white">The trade-off</div>
        <div className="text-sm leading-relaxed text-slate-300">8-bit is usually almost lossless. 4-bit is the common sweet spot: about 4 times smaller than 16-bit with a small quality drop. Below 4 bits quality falls faster, and tasks like math and code are often hit first. Always test on <em>your</em> task.</div>
      </div>
    </div>

    <h2 data-type="code" className="mb-6 border-l-4 border-teal-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      7. Python Implementation: Memory Math and Quantization From Scratch
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        This script calculates how much memory 7B and 70B models need at four precisions, quantizes a random weight matrix to int8 and int4, and compares one global scale with group-wise scales.
      </div>
      <div className="overflow-hidden rounded-2xl border border-white/10 bg-[#060911]">
        <div className="flex items-center justify-between border-b border-white/10 bg-white/[0.03] px-5 py-3">
          <span className="font-mono text-xs font-semibold text-teal-400">quantization_demo.py</span>
          <span className="font-mono text-[11px] text-slate-400">Python 3.10+ · NumPy only</span>
        </div>
        <pre className="overflow-x-auto p-6 font-mono text-sm leading-7 text-slate-200">
          <code>
            <span className="block">import numpy as np</span>
            <span className="block">&nbsp;</span>
            <span className="block text-slate-500"># 1. Memory needed just to store the weights</span>
            <span className="block text-cyan-300">def weights&#95;gb(params&#95;billion, bits):</span>
            <span className="block">    return params&#95;billion &#42; 1e9 &#42; bits / 8 / 1e9</span>
            <span className="block">&nbsp;</span>
            <span className="block">for bits, name in &#91;(32, &quot;float32&quot;), (16, &quot;float16 / bfloat16&quot;), (8, &quot;int8&quot;), (4, &quot;int4&quot;)&#93;:</span>
            <span className="block">    print(name.ljust(18), &quot;7B model:&quot;, round(weights&#95;gb(7, bits), 1), &quot;GB | 70B model:&quot;, round(weights&#95;gb(70, bits), 1), &quot;GB&quot;)</span>
            <span className="block">&nbsp;</span>
            <span className="block text-slate-500"># 2. Symmetric int8 quantization of a weight matrix</span>
            <span className="block">rng = np.random.default&#95;rng(0)</span>
            <span className="block">W = rng.normal(size=(256, 256)).astype(np.float32)</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def quantize(W, bits):</span>
            <span className="block">    qmax = 2 &#42;&#42; (bits - 1) - 1                          # 127 for int8, 7 for int4</span>
            <span className="block">    scale = np.abs(W).max() / qmax</span>
            <span className="block">    q = np.clip(np.round(W / scale), -qmax, qmax)</span>
            <span className="block">    return q, scale</span>
            <span className="block">&nbsp;</span>
            <span className="block text-cyan-300">def error&#95;after(W, bits):</span>
            <span className="block">    q, scale = quantize(W, bits)</span>
            <span className="block">    return float(np.mean((W - q &#42; scale) &#42;&#42; 2))</span>
            <span className="block">&nbsp;</span>
            <span className="block">print(&quot;Mean squared error int8:&quot;, format(error&#95;after(W, 8), &quot;.2e&quot;))</span>
            <span className="block">print(&quot;Mean squared error int4:&quot;, format(error&#95;after(W, 4), &quot;.2e&quot;))</span>
            <span className="block">&nbsp;</span>
            <span className="block text-slate-500"># 3. Group-wise quantization: one scale per small group of 64 weights fits better</span>
            <span className="block text-cyan-300">def error&#95;groupwise(W, bits, group=64):</span>
