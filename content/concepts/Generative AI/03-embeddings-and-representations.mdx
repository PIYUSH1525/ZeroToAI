The embedding lookup initially associates each token ID with a learned vector. Attention and the rest of the Transformer then transform those vectors based on the entire sequence.
      </div>

      <div className="grid gap-4 md:grid-cols-3">
        <div className="rounded-xl border border-cyan-500/25 bg-cyan-500/[0.04] p-5">
          <div className="mb-2 font-bold text-cyan-300">Initial</div>
          <div className="text-sm leading-relaxed text-slate-300">Token embedding selected from the learned embedding table.</div>
        </div>

          <div className="mb-2 font-bold text-violet-300">Context</div>

        </div>

        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-5">
          <div className="mb-2 font-bold text-emerald-300">Hidden State</div>
          <div className="text-sm leading-relaxed text-slate-300">The resulting representation carries information shaped by the current context.</div>
        </div>
      </div>
    </div>
  </section>

  <section>
    <h2 className="mb-6 border-l-4 border-orange-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      7. Intermediate: Position and Embeddings
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Token embeddings tell the model <strong className="text-orange-300">what token</strong> is present, but a sequence also needs information about <strong className="text-white">where</strong> each token occurs. This is the role of positional information.
      </div>

      <div className="rounded-2xl border border-orange-500/25 bg-orange-500/[0.04] p-6">

          Token Information + Position Information
        </div>

        <div className="flex flex-col items-center gap-3">
          <div className="w-full rounded-xl border border-cyan-500/30 bg-cyan-500/10 p-4 text-center">
            <div className="text-[10px] uppercase text-cyan-400">Token Embedding</div>
            <div className="mt-1 font-mono text-sm text-cyan-200">"cat" → learned vector</div>
          </div>

          <div className="text-orange-400">+</div>

          <div className="w-full rounded-xl border border-violet-500/30 bg-violet-500/10 p-4 text-center">
            <div className="text-[10px] uppercase text-violet-400">Positional Information</div>
            <div className="mt-1 font-mono text-sm text-violet-200">position 5 → position representation</div>
          </div>

          <div className="text-violet-400">↓</div>

          <div className="w-full rounded-xl border border-emerald-500/30 bg-emerald-500/10 p-4 text-center">
            <div className="text-[10px] uppercase text-emerald-400">Transformer Input Representation</div>
            <div className="mt-1 text-sm text-emerald-200">A representation containing token and positional information according to the architecture.</div>
          </div>
        </div>
      </div>

      <div>
        Different Transformer architectures handle positional information differently. Later in the course, you will encounter methods such as <strong className="text-cyan-300">learned positional embeddings</strong>, <strong className="text-violet-300">sinusoidal positional encodings</strong>, and <strong className="text-emerald-300">Rotary Positional Embeddings (RoPE)</strong>.
      </div>

      <div className="rounded-xl border border-amber-500/25 bg-[#0A0D16] p-5">
        <strong className="text-amber-300">Connection to the next modules:</strong>
        <span className="text-slate-300"> Embeddings answer "what is represented?" while positional mechanisms provide information needed to distinguish different positions in a sequence. Attention then uses these representations to model relationships between positions.</span>
      </div>
    </div>
  </section>

      9. Intermediate: Token Embeddings vs Sentence Embeddings
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        The word <strong className="text-pink-300">embedding</strong> is used in several contexts, so it is important not to confuse token embeddings inside an LLM with embeddings produced by dedicated embedding models.
      </div>

      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-cyan-500/25 bg-cyan-500/[0.04] p-6">
          <div className="mb-3 font-bold text-cyan-300">Token Embeddings</div>
          <ul className="space-y-2 text-sm leading-relaxed text-slate-300">
            <li>• Usually one initial vector per token position.</li>
            <li>• Stored as learned model parameters.</li>
            <li>• Feed into the Transformer computation.</li>
            <li>• Become transformed contextual representations.</li>
          </ul>
        </div>

        <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.04] p-6">
          <div className="mb-3 font-bold text-violet-300">Sentence / Text Embeddings</div>
          <ul className="space-y-2 text-sm leading-relaxed text-slate-300">
            <li>• Usually represent a larger piece of text with one vector.</li>
            <li>• Often produced by dedicated embedding models.</li>
            <li>• Common in semantic search and RAG.</li>
            <li>• Designed to make text similarity useful for downstream applications.</li>
          </ul>
        </div>
      </div>

      <div className="rounded-xl border border-amber-500/25 bg-amber-500/[0.04] p-5">
        <strong className="text-amber-300">Why this distinction matters:</strong>
        <span className="text-slate-300"> When you later learn RAG, you will work with text embeddings and vector databases. Those application-level embeddings should not automatically be assumed to be the same thing as the token embedding matrix inside a generative LLM.</span>
      </div>
