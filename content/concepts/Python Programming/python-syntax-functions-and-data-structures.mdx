In modern AI engineering, however, we combine dynamic execution with <strong className="text-cyan-300">Type Hints</strong> so IDEs and teams always know whether a variable holds a float, a list of tokens, or a tensor shape:

      3. Indexing, Slicing, and Mutability Traps
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Python sequences (Lists, Tuples, Strings, and later NumPy/PyTorch tensors) share a universal <strong className="text-white">Zero-Based Indexing and Slicing</strong> syntax: <code>seq[start : stop : step]</code>, where <code>start</code> is inclusive and <code>stop</code> is <strong className="text-emerald-300">exclusive</strong>:
      </div>
      <div className="grid gap-4 md:grid-cols-3">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">
          <div className="mb-1 font-mono text-sm font-bold text-cyan-300">tokens[0:3]</div>
          <div className="text-xs text-slate-300">Grabs indices $0, 1, 2$ (first $3$ items). Stop index $3$ is excluded.</div>
        </div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">
          <div className="mb-1 font-mono text-sm font-bold text-violet-300">tokens[-1]</div>
          <div className="text-xs text-slate-300">Negative index counts from the end (grabs the very last element).</div>
        </div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-5 text-center">
          <div className="mb-1 font-mono text-sm font-bold text-emerald-300">tokens[::-1]</div>
          <div className="text-xs text-slate-300">Step of $-1$ reverses the entire sequence cleanly.</div>
        </div>
      </div>
      <div className="rounded-2xl border border-rose-500/25 bg-rose-950/[0.15] p-6">
        <h3 className="mb-2 text-lg font-bold text-rose-300">The #1 Python Bug in ML: Reference Aliasing of Mutable Lists</h3>
        <div className="text-sm leading-relaxed text-slate-300">
          When you write <code>list_b = list_a</code>, Python <strong className="text-white">does NOT copy the list</strong>! Both variables point to the exact same list in memory. Mutating <code>list_b.append(99)</code> silently corrupts <code>list_a</code>! Always use <code>list_a.copy()</code> (shallow copy) or <code>copy.deepcopy(list_a)</code> (for nested 2D matrices/dicts) when duplicating mutable data.
        </div>
      </div>
    </div>
  </section>

        <div className="rounded-xl border border-orange-500/25 bg-orange-500/[0.04] p-6">

          <div className="mb-4 text-sm text-slate-300">
            Constructs the entire new list or dictionary in memory immediately. Ideal for normalizing feature arrays or inverting a tokenizer vocabulary:
          </div>
          <div className="rounded-lg bg-slate-950 p-3 font-mono text-xs text-slate-200">
            <span className="block text-slate-400"># List: [expr for x in iterable if cond]</span>
            <span className="block text-orange-300">squares = [x**2 for x in range(10) if x % 2 == 0]</span>
            <span className="block mt-2 text-slate-400"># Dict: Swap word-&gt;id to id-&gt;word</span>
            <span className="block text-cyan-300">id2word = &#123;idx: w for w, idx in vocab.items()&#125;</span>
          </div>
        </div>
        <div className="rounded-xl border border-cyan-500/25 bg-cyan-500/[0.04] p-6">

          <div className="mb-4 text-sm text-slate-300">
            Uses parentheses <code>(expr for x in iterable)</code> or the <code>yield</code> keyword inside a function. Produces <strong className="text-white">one item at a time on demand</strong> using $\mathcal{O}(1)$ memory!

          <div className="rounded-lg bg-slate-950 p-3 font-mono text-xs text-slate-200">
            <span className="block text-slate-400"># Streams 100GB file 1 batch at a time</span>

            <span className="block">    for i in range(0, len(data), size):</span>
            <span className="block text-emerald-300">        yield data[i : i + size]</span>
          </div>
        </div>
      </div>

    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      5. Functions, *args, **kwargs, Lambdas, and Decorators
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Functions in Python are <strong className="text-white">First-Class Objects</strong>—meaning you can pass a loss function or activation function as an argument into another function, return functions, and wrap them with decorators:
      </div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-6">
          <div className="mb-2 font-bold text-cyan-300">1. Positional, Default &amp; Keyword Arguments</div>
          <div className="text-sm leading-relaxed text-slate-300">
            Functions accept required positional parameters followed by optional default parameters (e.g., <code>def train(model, epochs=10, lr=1e-3):</code>). Passing keyword arguments explicitly (<code>train(net, lr=5e-4)</code>) prevents ordering bugs.
          </div>
        </div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-6">
          <div className="mb-2 font-bold text-violet-300">2. *args (Tuple) and **kwargs (Dict)</div>
          <div className="text-sm leading-relaxed text-slate-300">
            <code>*args</code> packs any number of extra positional arguments into a <strong className="text-white">Tuple</strong>, while <code>**kwargs</code> packs extra named keyword arguments into a <strong className="text-white">Dictionary</strong>. Used heavily when wrapping PyTorch layers and HuggingFace model configs!
          </div>
        </div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-6">
          <div className="mb-2 font-bold text-emerald-300">3. Lambda Functions (Anonymous Inline)</div>
          <div className="text-sm leading-relaxed text-slate-300">
            Single-expression inline functions defined with <code>lambda x: expr</code>. Most commonly used as custom sorting keys—such as sorting predicted classes by probability: <code>sorted(preds, key=lambda item: item[1], reverse=True)</code>.
          </div>
        </div>
        <div className="rounded-xl border border-white/10 bg-white/[0.03] p-6">
          <div className="mb-2 font-bold text-amber-300">4. Decorators (@torch.no_grad)</div>
          <div className="text-sm leading-relaxed text-slate-300">
            A decorator <code>@wrapper</code> is a higher-order function that wraps another function to modify its behavior without changing its source code—such as <code>@torch.no_grad()</code> to disable gradient tracking during LLM inference!
          </div>
        </div>
      </div>
      <div className="mt-8 rounded-2xl border border-amber-500/25 bg-[#0A0D16] p-6 shadow-[0_0_25px_rgba(245,158,11,0.05)]">

          <span>⚡ Knowledge Check </span>

        </div>

      <div className="space-y-6">
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Using a mutable list or dict as a default function argument (def fn(x, cache=[]):).
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Default arguments are evaluated only once when the function is defined. Mutating that default list leaks state across separate function calls! Always default to <code>None</code> and create a new list inside the function.
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Copying a list with b = a and assuming changes to b will not affect a.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Assignment only copies the memory reference, not the underlying list. Use <code>a.copy()</code> for 1D lists or <code>copy.deepcopy(a)</code> for nested structures.
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Creating a 2D matrix in Python using [[0] * cols] * rows.
          </div>

            Multiplying a nested list copies the reference to the <em>same</em> inner row $N$ times—so setting <code>grid[0][0] = 5</code> changes column $0$ in every single row! Always use <code>[[0] * cols for r in range(rows)]</code> or NumPy arrays.
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Using pure Python for-loops to multiply large numerical matrices.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Pure Python lists store boxed objects scattered across memory and check types on every iteration. Use Python lists/dicts for orchestration and I/O, and offload heavy math to vectorized NumPy or PyTorch tensors.
