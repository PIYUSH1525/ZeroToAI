    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        Beginners often chain brackets like <code>df[0:5][&quot;age&quot;]</code>, which causes unpredictable behavior and triggers Pandas&apos; notorious <code>SettingWithCopyWarning</code>. Instead, always use explicit accessors:

          <div className="mb-2 text-base font-bold text-cyan-300">1. df.loc[row_label, col_name]</div>
          <div className="mb-2 font-mono text-xs text-slate-400">Label-Based Indexing</div>
          <div className="text-xs leading-relaxed text-slate-300">

          </div>
        </div>
        <div className="rounded-xl border border-violet-500/25 bg-violet-500/[0.05] p-5">

          <div className="mb-2 font-mono text-xs text-slate-400">Integer Position Indexing</div>
          <div className="text-xs leading-relaxed text-slate-300">

        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.05] p-5">

          <div className="text-xs leading-relaxed text-slate-300">

      <h3 className="mt-8 text-xl font-bold text-white">Statistical Outlier Detection and Clipping ($Z$-Score vs. IQR)</h3>
      <div>
        A single corrupted sensor reading (e.g., an age entered as $999$ instead of $29$) can wildly distort the slope of Linear Regression or explode neural network gradients. We detect and cap outliers using two mathematical bounds:
      </div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-cyan-500/25 bg-cyan-500/[0.04] p-6">
          <div className="mb-2 font-bold text-cyan-300">1. Z-Score Standardization (Gaussian Data)</div>
          <div className="mb-4 text-sm text-slate-300">
            Measures how many standard deviations $\sigma$ a point lies from the mean $\mu$. Points with $|z| \gt 3$ ($99.7\%$ threshold) are flagged as outliers:
          </div>
          <div className="rounded-lg bg-slate-950 p-4 text-center text-sm">
            <div>$$z_i = \dfrac{x_i - \mu}{\sigma}$$</div>
          </div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-6">
          <div className="mb-2 font-bold text-emerald-300">2. Interquartile Range / IQR (Skewed Data)</div>
          <div className="mb-4 text-sm text-slate-300">
            Uses the $25\text{th}$ percentile ($Q_1$) and $75\text{th}$ percentile ($Q_3$) where $\text{IQR} = Q_3 - Q_1$. Cap values using <code>df[&quot;x&quot;].clip(lower, upper)</code>:
          </div>
          <div className="rounded-lg bg-slate-950 p-4 text-center text-sm">
            <div>$$[Q_1 - 1.5 \cdot \text{IQR}, \quad Q_3 + 1.5 \cdot \text{IQR}]$$</div>
          </div>
        </div>
      </div>

    <h2 className="mb-6 border-l-4 border-cyan-500 pl-4 text-2xl font-bold tracking-tight text-white sm:text-3xl">
      5. Advanced Production Pandas: Preventing Data Leakage, Method Chaining &amp; Memory Optimization
    </h2>
    <div className="space-y-6 text-[16px] leading-8 text-slate-300">
      <div>
        At the <strong className="text-white">Advanced / Production AI</strong> level, three skills separate senior ML engineers from beginners: <strong className="text-rose-300">Preventing Train-Test Data Leakage</strong>, <strong className="text-cyan-300">Vectorization &amp; RAM Optimization</strong>, and <strong className="text-emerald-300">Functional Method Chaining</strong>:
      </div>
      <div className="rounded-2xl border border-rose-500/30 bg-rose-950/[0.15] p-6">
        <h3 className="mb-2 text-lg font-bold text-rose-300">1. The #1 Production ML Bug: Train-Test Data Leakage in Pandas</h3>
        <div className="text-sm leading-relaxed text-slate-300">
          If you compute <code>df[&quot;age&quot;].fillna(df[&quot;age&quot;].median())</code> or normalize features across the <strong className="text-white">entire DataFrame BEFORE splitting into Train and Test sets</strong>, information from the unseen future Test set leaks into your Training set!
          <div className="mt-3 rounded-xl border border-white/10 bg-slate-950 p-4 font-mono text-xs text-emerald-300">
            Rule: Split Train/Test FIRST → Compute statistics (mean, median, IQR, target encoding) ONLY on Train → Apply those frozen Train statistics to both Train and Test!
          </div>
        </div>
      </div>
      <div className="grid gap-5 md:grid-cols-2">
        <div className="rounded-xl border border-cyan-500/25 bg-cyan-500/[0.04] p-6">
          <div className="mb-2 font-bold text-cyan-300">2. Why .apply(axis=1) is a Performance Trap</div>
          <div className="mb-3 text-sm text-slate-300">
            Calling <code>df.apply(fn, axis=1)</code> runs a slow Python-level loop over every single row, instantiating a new <code>Series</code> object per row ($300\times$ slower than C vectorization).
          </div>
          <div className="rounded-lg bg-slate-950 p-3 text-xs text-slate-200">
            <div><strong className="text-emerald-300">Speed Hierarchy (Fastest to Slowest):</strong></div>
            <div className="mt-1 font-mono">1. NumPy / Pandas Vectorized Ops (C/PyArrow)</div>
            <div className="font-mono">2. np.where(cond, a, b) / np.select()</div>
            <div className="font-mono text-rose-300">3. df.apply(..., axis=1) / iterrows() (Avoid!)</div>
          </div>
        </div>
        <div className="rounded-xl border border-emerald-500/25 bg-emerald-500/[0.04] p-6">
          <div className="mb-2 font-bold text-emerald-300">3. Slashing RAM Usage by 80% (Dtypes &amp; PyArrow)</div>
          <div className="mb-3 text-sm text-slate-300">
            By default, Pandas loads numbers as 64-bit (<code>float64</code>, <code>int64</code>) and strings as Python pointers (<code>object</code>). On a 20M-row dataset, you can cut RAM by $70\text{--}85\%$:
          </div>
          <div className="rounded-lg bg-slate-950 p-3 font-mono text-xs text-slate-200">
            <div>• Low-cardinality strings → .astype(&quot;category&quot;)</div>
            <div>• 64-bit floats → .astype(&quot;float32&quot;) (matches GPU!)</div>
            <div>• Pandas 2.0+ → dtype_backend=&quot;pyarrow&quot;</div>
            <div>• Disk I/O → Save as .parquet instead of .csv</div>
          </div>
        </div>
      </div>
      <div className="mt-8 rounded-2xl border border-amber-500/25 bg-[#0A0D16] p-6 shadow-[0_0_25px_rgba(245,158,11,0.05)]">
        <div className="mb-2 flex items-center gap-2 text-xs font-bold uppercase tracking-widest text-amber-400">
          <span>⚡ Knowledge Check </span>
        </div>
        <div className="mb-5 text-base font-semibold text-white">
          You are imputing missing values in <code>df[&quot;income&quot;]</code> before training an XGBoost model. Why is calling <code>df[&quot;income&quot;] = df[&quot;income&quot;].fillna(df[&quot;income&quot;].median())</code> on the full dataset BEFORE calling <code>train_test_split(df)</code> a critical error?
        </div>

      <div className="space-y-6">
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Chained indexing assignment like df[df[&quot;age&quot;] &gt; 30][&quot;status&quot;] = &quot;senior&quot;.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Chaining two bracket operations often modifies a temporary copy in memory that is immediately discarded, leaving <code>df</code> unchanged and triggering <code>SettingWithCopyWarning</code>. Always assign in one step using <code>df.loc[df[&quot;age&quot;] &gt; 30, &quot;status&quot;] = &quot;senior&quot;</code>.
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Using Python keywords (and / or / not) instead of bitwise operators (&amp; / | / ~) in masks.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            In Pandas, <code>df[(df[&quot;a&quot;] &gt; 1) and (df[&quot;b&quot;] &lt; 5)]</code> throws a <code>ValueError: The truth value of a Series is ambiguous</code>. Always use <code>&amp;</code>, <code>|</code>, and <code>~</code> with each condition wrapped in parentheses.
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Imputing missing values or target-encoding categories before splitting Train and Test.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            Calculating means, medians, or group target averages across the full DataFrame leaks test-set information into training features, producing artificially high validation scores that fail in production.
          </div>
        </div>
        <div>
          <div className="mb-1.5 font-bold text-rose-400">
            ✕ Iterating over DataFrame rows with for idx, row in df.iterrows():.
          </div>
          <div className="text-sm leading-relaxed text-slate-300">
            <code>iterrows()</code> boxes every single row into a new Pandas Series object in Python, turning a $5$-millisecond vectorized C operation into a $30$-second bottleneck.
          </div>
